**모달 딥링크 (2026-07-27, "링크 만들 수 있는 모든 곳에 URL")** — 공용 훅
`app/hash-modal.ts`의 `useHashSync(value, apply)`가 모달 상태 ↔ 해시를 양방향 동기화한다
(열림 pushState → 뒤로가기로 닫힘 · 모달 내 전환 replaceState · UI 닫기는 해시 제거).
vinext의 pushState 패치(스크롤 리셋)를 피하려 네이티브 `History.prototype.pushState`를 부른다.

> ⚠ **`location.hash = "#…"` 대입 금지 (2026-08-13 실측).** 해시 대입은 vinext의 RSC
> 내비게이션(`__VINEXT_RSC_NAVIGATE__`)을 타는데, Pages 정적 배포에선 그 페이로드를 못 받아
> **무한 재시도**에 빠진다. 거기서 쏟아지는 popstate가 `useHashSync`의 `apply()`를 계속 불러
> **닫은 모달이 즉시 다시 열린다** (홈 포탈의 '업데이트 내역' 타일에서 발생 — 클릭 1회에
> RSC 내비 75회·popstate 45회/2초). **로컬 서버(`vinext start`)에선 1회로 끝나 재현되지 않는다**
> — 이런 증상은 라이브에서 확인할 것. 밖에서 모달을 열 땐
> `History.prototype.pushState.call(history, null, "", "#…")` + `dispatchEvent(new Event("hashchange"))`.

- **⚠ 크롤러용 앵커는 푸터가 책임진다 (2026-07-28 색인 사고)**: 헤더 탭·언어 전환기가 전부
  **버튼(SPA 전환)**이라 정적 HTML에 내부 링크가 하나도 없었고, 검색엔진에는 모든 탭이
  **고아 페이지**였다 (GSC "발견됨 — 현재 색인이 생성되지 않음": /stories·/en/stories·
  /ja/stories·/ja/about). 푸터의 `.footer-tabs`(탭)·`.footer-langs`(언어)가 유일한 실제
  `<a href>`이므로 **지우거나 버튼으로 바꾸지 말 것**. href는 반드시 **쿼리 없는 정본 경로**
  (`tabPath()`는 `?future=1`을 실어 나르므로 링크에 쓰지 않는다 — 파라미터 URL이 색인
  후보로 잡히면 "대체 페이지"만 늘어난다). 클릭은 preventDefault→`switchTab`으로 SPA 유지,
  수식어·중클릭은 브라우저 기본 동작에 맡긴다.
- **sitemap `lastmod`**: Google은 `changefreq`·`priority`를 **무시하고 lastmod만** 크롤 신호로
  쓴다. 빌드 시각을 넣으면 안 바뀐 페이지까지 갱신됐다고 거짓 신고하는 꼴이라 Google이
  lastmod 자체를 불신하게 된다 — 그래서 **탭별 데이터 파일의 마지막 git 커밋 시각**을 쓴다
  (`SEG_SOURCES` 맵). 새 탭을 추가하면 이 맵에도 데이터 파일을 등록할 것.

### 헤더 **유니버셜 서치** (2026-07-25, 사용자 요청)

화면 이름은 **유니버셜 서치** — 사이트 전체를 한 번에 찾는다는 뜻.
**인게임 용어(테라·PRTS 등)를 쓰지 말 것** (사용자 확정: 검색 기능 이름은 현실 세계 단어로).
코드·파일명은 `omni*`(omni.ts / omni-search.tsx / omni-picks.ts).

헤더 1줄(햄버거 왼쪽)의 `⌕ 유니버셜 서치` 버튼 — **헤더를 접어도 남는다**. ⌘K/Ctrl+K, `/`로도 열린다.
단어를 넣고 **[바로가기]**(또는 ⏎)를 누르면 1위가 확실하면 곧장 이동하고, 애매하면
"이 중에 무엇인가요?" 선택지를 띄운다. 검색은 타이핑이 멈춘 뒤 0.5초에 돈다(아래 공통 규칙).

**매칭 4단(app/omni.ts)** — 위에서부터 시도하고, 약할 때만 아래로 내려간다.

1. **정확 매칭** — 완전일치(120) > 접두(≤100×덮는비율) > 부분(≤60×비율), 별명·코드 −8.
   이름은 **띄어쓰기 단위로도** 키에 넣어 "던스트릭"→첸 더 던스트릭, "커버넌트"→엑시아 더 뉴 커버넌트.
2. **조합 별칭(완전일치 전용, 키 앞에 `=`)** — 부분일치로 새면 잡음이라 정확히 쳤을 때만 맞는다.
   - **이격(알터)**: 알터 이름은 항상 "원본 + 수식어"라 첫 토큰이 다른 오퍼 이름이면 이격으로 보고
     `이격첸`·`첸이격`·`첸알터`·`알터첸`·`첸 alter`를 자동 생성 (2026-07 현재 28명, 로케일 무관).
   - **통합전략 테마 별명**: `TOPIC_NICKS`(팬텀·미즈키·사미·살카즈·쉐이·블랙플로우 …) ×
     분류어(록라·로라·로그라이크·통합전략·통전) → `사미록라`·`팬텀록라` 전부 매칭.
     테마와 같은 이름의 스토리 이벤트에도 같은 별명이 붙는다("사미" → 테마 + 스토리).
3. **여러 낱말 = 범위 + 이름 조각** (사용자 요청 2026-07-26): `사미 글로리` = 범위(사미 테마)
   + 이름 조각(글로리) → 탐험가의 은빛 서리 끝자락의 《글로리어스 카시미어》. 범위 낱말은
   **테마 별명**(사미·미즈키·팬텀…, `사미록라`처럼 분류어가 붙어도 됨) · **분류어**(스토리·재료…) ·
   **섹션어**(유물·조우·작전·구역·분대·음반·부품·엔딩·사고). 이름 조각은 **전부 맞아야** 한다(AND).
   범위만 주면(`쉐이 조우`) 그 테마의 해당 **화면**으로, `사미 스토리`면 그 테마 이름의 스토리로 간다.
   ⚠ 통합전략 항목 이름은 《글로리어스 카시미어》·'글로리 팩'처럼 장식 문자를 달고 있어서,
   omni의 정규화는 normSearch 위에 **괄호·따옴표·하이픈류를 한 번 더 제거**한다(DECOR).
4. **분류 힌트(붙여 쓴 경우)** — "쉐이록라" = 이름(쉐이) + 분류어(록라). 내장 사전(`HINT_TOKENS`: 록라/로라/
   통전/스토리/썰/이벤트/재료/파밍/공채/태그/오퍼…)에서 분류어를 떼고 남은 이름을 그 종류에서만
   찾아 +34. **새 은어는 학습한다** — 되묻기에서 고른 항목의 이름을 검색어에서 뺀 조각을
   (조각 → 종류)로 기억해, "미즈키갓겜"에서 테마를 고르면 다음부터 "쉐이갓겜"도 통한다.
5. **오탈자 근사** — 한글을 **자모로 분해**해 2-그램 Dice 유사도 ≥0.55면 후보로 올린다
   ('첸 더 더스트릭'→첸 더 던스트릭, '네스티'→내스티. 둘 다 자모 한 개 차이라 음절 단위론 못 잡는다).
   앞 단계들의 최고점이 72 미만일 때만 돌고, 점수는 30~85라 완전일치(120)를 절대 못 넘는다.
   목록에 '비슷한 이름' 배지가 붙는다. 자모 4개(2음절) 미만 검색어에는 돌리지 않는다(잡음).

**색인 대상**: 오퍼(이름·다국어 별칭·이격 별명·코드) → `#op-` 모달 /
스토리 → `#story-` / 재료(은어 별칭) → 파밍 상세 모달 / 공채 태그 → 태그 선택 /
통합전략 테마 → `?topic=isN` / **통합전략 화면**(맵·노드·적 도감·소장품·전시관·난이도·엔딩)과
**전시관 서브탭**(암호판·사고·레퍼토리…, 지연 로드 시 mech 엔트리의 arc 라벨에서 유도) /
기능 탭(riic·base·is3 동의어). **미래시 꺼짐이면 미실장 오퍼·재료·CN 선행 테마는 빠진다.**

**통합전략 세부 항목**(유물·조우·작전·구역·분대·시스템)은 스샷 레이더 인덱스(2.9MB)를 그대로
재사용하되 무거워서 기본 색인엔 없다 — 가벼운 색인이 빈손일 때 자동으로, 또는 푸터 버튼으로
세션 1회 지연 로드. `/rogue`에서는 **현재 테마를 사전확률로** 써서 테마 공용 동명 항목
(뱀파이어의 침대·전시관 등)의 동점을 그 테마로 확정한다(렌즈 CTX_BOOST와 같은 판단).

**학습은 전부 DB에 쌓인다** (`app/omni-picks.ts` + `app/trail.ts` + `docs/supabase-omni-picks.sql`).
사용자 확정 2026-07-25: **"모두가 검색해서 빅데이터를 쌓아야 하니 가중치는 기본적으로 DB에."**
브라우저에는 학습 데이터를 두지 않는다 — localStorage에 있는 건 익명 세션 id 하나뿐이고
(표 중복 제거용), sessionStorage는 쓰지 않는다.

- 클라이언트가 보고하는 **사실 3종**(전부 `omni_pick` 한 표에 `source`로 구분):
  `pick`(되묻기에서 직접 고름) · `miss`(그 검색어로 0건이었다) · `visit`(이 컨텐츠에 도착했다).
  pick 행에는 rank(고른 후보 순위)·candidates·fuzzy·hinted도 함께 남아 품질 점검에 쓰인다.
- **실패한 검색 → 최종 목적지 연결은 DB가 한다** (`omni_trail_counts`): 같은 세션에서
  miss 뒤 **10분 안의 방문 5곳까지**를 짝짓는다. "날시"(0건) → 백과사전에서 켈시 이격 클릭
  = (날시 → 그 오퍼) 한 표. **목적지는 여럿일 수 있다** — 야토=야토/키린R야토,
  켈시=켈시/Kal'tsit·Esperanta, 성녀=프라마닉스/프라마닉스 더 프레리타처럼 후보가 둘 이상인
  말이 흔해서, 첫 방문 하나만 잡지 않고 창 안의 방문을 모두 쌓는다(사람들이 더 많이 가는
  쪽이 위로, 비슷하면 되묻기).
- 사이트가 읽는 건 합쳐 놓은 뷰 하나 `omni_weights(q, uid, voters, trail_voters)`.
  **가중 = voters + 0.5×trail_voters**, 보너스 = `min(45, 18+9·log2(1+가중))`:
  1표 = 27점(1순위로 오르되 되묻기 유지) · **2표 = 32점(확신 문턱 30 초과 → 바로 이동)**.
  즉 **서로 다른 두 사람이 같은 답을 고르면 확정**된다. 상한 45라 학습이 비슷한 후보의
  순서만 바꾸고 완전일치(120)를 못 넘는다.
- **글자가 하나도 안 맞아도 결과에 주입한다** — "날시"는 어떤 이름과도 안 겹치지만 학습된
  가중치가 있으면 `LEARNED_BASE(55) + 표 보너스`로 후보에 올린다(searchSmart 주입 단계).
  이게 없으면 학습된 별명은 영영 화면에 못 나온다.
- 내가 방금 만든 pick 표는 서버 왕복 없이 메모리 지도에 얹혀 같은 세션에서 즉시 반영되고,
  다음 접속엔 DB에서 돌아온다. trail은 DB가 짝지으므로 **다음 접속부터** 반영된다.
- `omni_miss_top`(무슨 말로 검색했는데 0건이었나) · `omni_query_top`(인기 검색어·평균 순위)은
  별칭·힌트 사전을 보강할 때 보는 통계다. 아직 사이트가 읽지는 않는다.
- 알려진 한계: visit 보고는 "최근 10분 안에 못 찾은 검색이 있었나"를 **메모리 플래그**로
  가늠한다 — 미스 직후 **새로고침**하면 그 한 번의 연결은 놓친다(SPA 탭 이동은 안전).
  전부 잡으려면 그 타임스탬프 하나만 sessionStorage에 두면 된다.

**이동은 새 라우팅을 만들지 않고 기존 경로를 탄다**: 해시 딥링크(`#op-`/`#story-`),

### 검색 입력 공통 규칙 — **비제어 입력 + 0.5초 디바운스** (사용자 확정 2026-07-25)

**사이트의 모든 검색 입력은 `app/search.ts`의 `useSearchInput()`을 쓴다.** 두 가지를 동시에 한다:

1. **비제어(uncontrolled)** — 입력값은 DOM에만 있고 리액트 상태가 아니다. 제어 입력
   (`value={state}`)은 한 글자마다 화면을 다시 렌더한 뒤에야 글자가 보이므로, 목록이 큰
   화면(오퍼 420장)에선 **입력 자체가 굼떠진다** — 특히 한글 IME 조합 중
   (사용자 리포트 2026-07-25: "오퍼 검색할 때만 인풋 하나하나가 너무 느리다").
   → 타이핑 중 리액트 렌더 **0회**. 실측 JS 처리 8~10ms → **0ms**.
2. **0.5초 디바운스** — 타이핑이 멈춘 뒤에만 `term`이 갱신돼 목록이 한 번 그려진다.
   (처음 1초였다가 "너무 느리다"는 지적으로 0.5초로 내림 — 다시 올리지 말 것.)

```ts
const { term, set, clear, inputRef, inputProps } = useSearchInput();
<input {...inputProps} placeholder="…" />          // term으로 필터링
```

| 화면 | 입력 |
|---|---|
| 헤더 유니버셜 서치 | 자체 타이머(같은 0.5초) — [바로가기]·⏎는 **기다리지 않고 즉시** 검색 |
| 오퍼 백과사전 | `#operator-search` (× 지우기·활성 칩·초기화는 `clear()`) |
| 재료 파밍 / 육성 비용 계산기 | 재료 검색(`set()`으로 모달의 '효율표에서 검색' 연동) · 오퍼 추가 |
| 인프라 플래너 | 보유 오퍼 설정(450칩) · 방 모달 후보 검색 |
| 통합전략 | 노드·적·소장품 (테마 전환·렌즈 도착 시 `set("", false)`로 조용히 초기화) |
| 스토리 검색 | 드롭다운 열기(`setSearchOpen`)는 onInput에 합성 |
| 공채 태그 빠른 입력 | 태그 자동선택·조합 계산도 함께 지연, 클리어는 `set("")` |
| 스샷 스캐너 | 빠진 오퍼 직접 추가 |

- **지우기(빈 문자열)는 기다리지 않는다** — 초기화는 즉시 반영.
- 입력이 비었는지를 **상태로 들고 있지 않으므로**, 지우기(×) 버튼 표시는 CSS로 한다:
  `input:placeholder-shown ~ .search-clear { display: none }` (`.omni-clear`·`.omni-go`도 동일).
- 프로그램에서 값을 넣을 땐 `set(value)` — DOM value와 term을 함께 맞춘다(입력이 마운트돼
  있어야 한다. 언마운트 상태에서 넣는 값은 `""`만 안전 — defaultValue와 같기 때문).
- 큰 목록은 **요소 단위로 memo**한다 — 오퍼 그리드는 `useMemo(() => <div>…420장</div>, [sorted, onSelect])`
  로 감싸 필터 렌더에서 재조정을 건너뛴다. 필터 칩의 개수 배지도 렌더마다 로스터를 훑지 말고
  `chipCount` 맵으로 한 번에 집계한다(컨셉덱만 40종×420명 = 1.7만 회 스캔이었다).
- 만능검색 패널의 오버레이에 `backdrop-filter`를 다시 넣지 말 것 — 매 키 입력마다
  전체 화면을 블러로 재합성한다(실측 프레젠테이션 딜레이 130~380ms의 주범).

python3 scripts/build-infra.py <dir>      # 5. 인프라 데이터 재생성 → app/data/infra.json (rules.json의 파서 상수·교정 반영)
node scripts/verify-plan.mjs              # 5-1. 플래너 회귀 검증 (정배 픽스처 — INFRA-RULES §10)

### 확정된 데이터 규칙 (사용자가 직접 교정한 것 — 어기면 안 됨)

1. **가짜 게스트 오퍼 제외**: `isNotObtainable == true` 이면서 **모듈 데이터가 있는** 항목은
   스토리용 가짜 데이터 → 제외 (char_608~617 계열: 6성판 샤프·피스·튤립·미저리·스톰아이·
   메커니스트·로드·샤프·라이디언 중복판·터치·맹약 서포터). 모듈 없는 획득 불가 오퍼
   (5성 A팀 샤프·스톰아이·튤립·피스)는 실사용 가능하므로 **유지**. 430→420명이 된 이유.
2. **KR 출시순 = handbook_info_table 키 순서** (`seq` 필드로 방출). char id 번호는 CN 배정
   순서라 정렬에 쓰면 안 됨. 핸드북에 없는 예비 인원류는 seq=-1로 맨 뒤.
3. **이미지 로컬화**: 데이터의 `image`는 `/avatars/<char_id>.png` 경로. 신규 오퍼는
   download-avatars.py로 받아온다 (레포에 24MB 커밋되어 있음).
4. **인프라 스킬 강화/신규 구분**은 building_data의 buffChar **슬롯 구조**가 정답
   (같은 슬롯=강화 단계→최종만, 다른 슬롯=동시 적용). 이름 휴리스틱 금지. → INFRA-RULES.md §2
5. 세부직군 명칭은 uniequip_table의 subProfDict 기준 (예: 네크라스=셰이퍼 캐스터).
6. KR 용어: 금괴 아님 → **순금/귀금속류**, 무인기 아님 → **드론**, 연소 원소 = **소각 손상**.

### 컨셉덱 태그 규칙 (`retag-concepts.py`)

- 태그는 스킬·재능·특성·모듈 텍스트를 규칙 엔진으로 훑어 재부착한다 (수동 태그 아님).
- **시너지 팟 11종** — 컨셉 필터 **최상단 고정** (home.tsx의 `SYNERGY_POTS` 순서):
  `어비설팟(어비설) · 쉐이팟 · 쉐라그팟 · 카시미어팟 · 미노스팟 · 아베무팟(Ave Mujica 콜라보) ·
  소각팟 · 라테라노팟 · 탄약팟 · 라인랩팟 · 라이오스 파티(던전밥 콜라보)`
- 팟 판정 = **앵커 진영 소속 OR 전투 텍스트 언급** (POT_BY_FACTION / POT_BY_TEXT / POT_EXTRA):
  - 출신지만으로 붙이지 말 것: 에기르 출신 ≠ 어비설팟 (루실라·언더플로우·딥컬러 제외,
    스카디 더 커럽팅 하트는 재능 텍스트로 포함).
  - 이벤트 맵 조건은 시너지 아님: 쉐이팟 텍스트 규칙은 "쉐이 **오퍼레이터**" 언급만
    ("[쉐이의 기이한 계원]에서" 같은 전장 환경 조건 제외 — 라이디언 사례).
  - 소각팟 = 텍스트 "소각" + 수동 추가(골든글로우, 라플란드 더 데카덴차 — 소각 게이지를
    실질 축적하는 고빈도 술딜러, 사용자 확정).
  - 쉐라그팟 = 쉐라그 + 카란 무역회사 두 진영.
- 정규식 주의: 필러에 `[^%\d]` 계열 사용 (백트래킹이 숫자를 먹어 "50% 상승"→"0%"가 된 버그 전례).
  한글 이름 매칭은 음절 경계 `(?<![가-힣])` 주의 ('레이'가 '오퍼레이터'에 매칭된 전례).
- **스킬·재능 '이름'은 판정에 쓰지 않는다** (2026-07 사용자 규칙). `corpus()`는 특성·설명·모듈
  효과만 본다 — '침묵의 소리'(에벤홀츠)·'묵음의 속박'(만트라)·'금빛 수면'(머틀) 같은 연출용
  명칭이 실제 효과로 오인되던 문제 제거.
- **"침묵" 컨셉 부활 (2026-08-08, 사용자 제보 "라플란드 같은애들이 침묵 가지고 있음")** —
  2026-07에 이름 판정을 없애자 매칭이 0명이 되어 컨셉을 통째로 삭제했었는데, **원인 진단이
  틀렸다**. 실제 효과가 없었던 게 아니라 **KR 데이터가 '침묵'이라는 낱말을 아예 쓰지 않는다**:
  게임 표기는 **"특수 능력 무효화"**다(라플란드 재능 '정신 파괴': "공격 시 적의 특수 능력
  무효화, 6초간 지속"). '침묵'은 커뮤니티 용어다.
  → 태그 이름은 통용어 **"침묵"**, 판정은 게임 문구 `특수 능력[^.]{0,10}무효화`.
  시간 표현이 끼는 변형까지 받는다("특수 능력을 5초간 무효화" 코로세럼 / "특수 능력 7초간
  무효화" 스카이박스). 대미지·은신 무효화는 안 걸린다.
  **해당 8명**: 라플란드 · 라플란드 더 데카덴차 · 첸 더 던스트릭 · 오올헤약 · 스노우상트 ·
  스카이박스 · 코로세럼 · 프로바이조.
  교훈: **태그가 0명이면 지우기 전에 게임이 그 효과를 뭐라 부르는지부터 확인할 것.**
- `corpus()`는 텍스트 단위(특성/스킬설명/재능설명/모듈효과)를 **마침표로 join** — `[^.]` 정규식이
  스킬 경계를 넘어 오탐 내던 문제 방지(프란카 자기 방어력 감소가 옆 스킬 '적'과 붙던 사례 등).
- **반사(가시)** = `is_reflect()`: 피격/공격받음/회피·패리 성공 → 공격자·목표·적에게 대미지/손상/반격.
  호시구마·니엔·쏜즈(호신용 가시)·버블·페넌스·테킬라·체르니·무에나·호시구마 더 브리처·위·필라에·

## 4. 오퍼 백과사전 탭 (app/home.tsx)

- **필터** 순서 고정: **컨셉덱 → 성급 → 직군 → 세부 직군 → 전투 태그 → 공격 방식 → 공식 소속**.
  - **컨셉덱은 검색**이다 (사용자 확정 2026-08-01, 종전 태그 40여 개 벽에서 전환).
    입력 + 검색 버튼(또는 Enter)으로만 필터가 걸리고, 입력 중에는 **드롭다운으로 후보만** 뜬다
    (입력이 비면 전체 목록 — 태그 벽 없이도 훑어볼 수 있다). **한 번에 하나만** 고르며
    새로 고르면 앞의 것을 밀어낸다. 별칭 사전(“슬로우”→감속·정지, “록라모듈”→통합전략 전용
    모듈)은 [app/concepts.ts](../app/concepts.ts) — 태그가 아닌 조건은 거기 `SPECIAL_CONCEPTS`에
    술어로 넣고 키를 `@`로 시작시켜 태그 키와 겹치지 않게 한다.
    ⚠ **한글 IME**: 조합 중의 Enter는 글자 확정이라, 거기서 입력을 비우면 확정된 글자가 뒤늦게
    다시 들어와 “탄약”→“약”처럼 한 글자가 남는다. `isComposing`이면 미뤘다가 `compositionend`
    **다음 틱**에 검색한다(그 사이 input 이벤트가 한 번 더 온다).
  - **세부 조건**(성급·직군·…)은 카테고리를 누르면 값이 **떠 있는 드롭다운**으로 나온다.
    값은 여전히 토글 다중선택이라 고르는 동안 열려 있고, 바깥 클릭·ESC로 닫힌다.
    (2026-08-01 이전에는 아래로 밀어내는 인라인 목록이었다.)
  - 값 필터는 전부 토글 다중선택, "전체" 버튼 없음 (모두 해제 = 전체). 컨셉덱만 단일 선택.
  - DATA NOTE 안내 박스는 삭제됨 (사용자 판단 "의미가 없어보임", 2026-08-01).
- **공격 방식** = 근거리/원거리(position) + 물리/마법(특성에 "마법 대미지" 포함 여부로 판정).
- **정렬**: 기본 = **성급 내림차순 → KR 출시 최신순(seq)**. 그 외 이름/성급/소속/출신지/종족/직군/세부직군.
  방향 토글(↑↓) 있음.
- **카드 그리드**: 한 줄 5명 (≤1450px 4 / ≤1100px 3 / ≤760px 2 / ≤430px 1).
  카드 초상화는 min-height라 이름이 길면 늘어남 (소속·출신·종족이 잘리면 안 됨).
- **카드/모달 공통 표기**: 이름 아래 공식 소속·출신지·종족.
- **스킬 공격 범위**: 스킬이 범위를 바꾸면(`skill_table` levels의 `rangeId`, KR 228개) 스킬 카드에
  기본 범위와 겹친 격자를 보여준다 — 늘어난 칸은 채우고 빠지는 칸은 점선. 범위가 **레벨을 타는**
  스킬 4개(메이어·스와이어·슈바르츠·아스베스토스)는 `public/skills/`의 `rg`/`ri`로 Lv 탭을 따라간다.
  기본 범위와 **같은 칸이면 아예 표시하지 않는다** (Mon3tr '책략: 초연결'처럼 rangeId만 붙고 실제로는
  안 바뀌는 스킬 14건 — 사용자 지적 2026-08-01).
  ⚠ 표시되는 범위가 본체가 아니라 **소환물** 것인 경우가 있다(메이어 '교란 장치' 등) — 클뜯에 구분
  플래그가 없어 **소환물이 같은 이름의 스킬을 갖고 있고 본체 스킬도 같은 범위를 들고 있을 때만**
  (= 교차 검증될 때만) "소환물 ○○의 범위"로 돌린다.
  ⚠⚠ **소환물 스킬의 rangeId는 실제 게임과 다를 수 있다.** 돌·장치의 발동 범위는 prefabId(스킬 로직)로
  계산돼 rangeId에 안 실린다 — 왕 '천하겁'은 게임에선 반경2 마름모(13칸)인데 데이터엔 십자 9칸(x-6)만
  있고 그건 오히려 S2 모양이다(KR·CN 모두 마름모 참조 없음). 이런 건 `regen-operators.py`의
  **`SUMMON_SKILL_RANGE`**에 손수 확인한 값을 적는다(격자는 range_table의 기존 id를 빌려 쓰고,
  note는 i18n 키). 손수 넣은 값이 유추보다 우선한다.
- **미래 모듈**: 이미 KR에 실장된 오퍼에 중섭에서만 추가된 모듈(피아메타 통합전략 전용 ISW-A 등
  실측 18건)은 `regen-operators`가 CN uniequip에서 따로 긁어 `modules[].unreleased`로 표시한다.
  화면은 **'미래시 포함' 토글이 켜졌을 때만** 보여주고 카드에 '미실장' 뱃지를 단다.
  매 갱신마다 `scripts/audit-modules.py`가 현황을 훑는다 (fast 레인).
- **소환물(토큰)**: `displayTokenDict`가 정본 (KR 48 + CN 선행 5). 스탯·범위·재능·스킬을 오퍼와
  같은 방식으로 뽑아 `operators.json`의 `summons`에 넣고, **재능 섹션(04) 안**에 카드로 보여준다 —
  재능 문구가 "○○를 소환할 수 있다"라고 알려 주는 경우가 대부분이라 같이 읽힌다 (사용자 요청).
  소환물 스킬의 범위 격자는 소환물 카드가 아니라 **같은 이름의 본체 스킬 카드**에 붙고, 본체 범위와
  **한 줄에 나란히** 놓는다(점선 세로선으로 구분). 토큰은 같은 스킬을 슬롯 수만큼 반복해 갖고 있어
  (위셔델 '레버넌트의 그림자' 3회 등 31종) 이름·설명이 같으면 하나로 접는다. 개체가 여럿인 소환물
  (실버애쉬 더 레인프로스트의 '눈보라의 눈')은 스탯·스킬이 완전히 같을 때만 합치고 `count`로 마릿수를 낸다.
- **오퍼 상세 모달**: 내용 순서 = 잠재→스탯→스킬→재능(+소환물)→특성→모듈→인프라→스킨→프로필→보이스 대사.
  헤더 오른쪽에 **육성 비용 계산** 버튼 — `/upgrade?ops=<id>`로 그 오퍼를 담아 이동한다.
  오른쪽에 **목차 레일**(`.modal-rail`, 2026-08-01)이 붙어 누르면 그 섹션으로 스크롤한다 —
  각 `<section className="detail-section" id="op-…">`와 `MODAL_SECTIONS` 배열이 1:1이니
  섹션을 더하거나 지우면 **둘 다** 고쳐야 한다. 760px 이하에선 본문 폭을 먹어 숨긴다.
  섹션 offsetTop이 스크롤러 기준이어야 해서 `.modal-scroll`은 `position: relative`다.
  복장·프로필·보이스·**스킬 레벨 수치**·모듈 이야기·**오퍼레이터 기록(밀록)**은 **모달을 열 때만
  오퍼당 파일 1개를 받아오는 지연 로딩**이다
  (`public/{skins,profiles,voice,skills,modules,records}/<locale>/<id>.json`, R2 서빙). 목록 화면에
  통째로 실리는 operators.json에 넣으면 첫 로딩이 무거워지기 때문 — 새로 큰 텍스트를 붙일 땐 이 관례를 따른다.
  기록(`RecordSection`, 2026-08-18)은 `scripts/build-records.py`가 AVG 스크립트를
  build-story-scripts.py 파서로 파싱한 것 — 열람 창은 스토리 탭 `ScriptReader`를 lazy 재사용한다.
  CN 선행 기록(`f:1`)은 미래시 토글이 켜졌을 때만 보이고 중국어 원문 안내가 붙는다.
  build-records는 **ci-refresh 미포함**(원문 fetch 1,100건) — kr-big-patch 로컬 단계에서 돌린다.
  스킬은 **레벨 탭 한 줄**(1~7 · M1~M3)로 Lv별 수치를 보여 준다 (사용자 요청 2026-08-01
  "밑으로 쭉 늘어지지 않게") — 문장 속 숫자를 그 자리에서 갈아 끼우고 바뀌는 값만 강조한다.
  데이터가 오기 전에는 operators.json의 최고레벨 `description`을 그대로 쓴다(빌드에서 일치 검증).
  오퍼레이터 파일 문서(기본정보·종합검진·프로필…)는 **전부 접었다 폈다** 되며, 해금이 걸린
  문서만 접힌 채로 시작한다 (사용자 요청 2026-08-01).
  보이스 대사는 음성 파일 없이 **텍스트만** 수록한다 (사용자 확정 2026-07-31,
  파이프라인·중복 함정은 [scripts/README.md](../scripts/README.md) §7.5).
  상단 히어로(사진+이름)는 모달의 ~20%만 차지 (compact). 열면 `#op-<id>` 해시.
  모바일 뒤로가기로 닫힘(pushState/popstate), iOS는 dvh로 상단 잘림 방지.
- **오퍼 얼굴 = 상세 모달 (전 시스템 공통 규칙)**: 모든 탭·모달에서 오퍼 아바타를 클릭하면

  단 함선 미리보기의 일반 시설 타일은 방 모달을 여는 버튼이라 예외.

  한때 "적용만"으로 바꿨다가 사용자가 재확정). 메인 버튼 문구는 "자동편성 실행".

제안 모달이 **게시판(스레드 목록)** 이다: 내가 보낸 제안 + 개발자 답변을 **작성자 본인과
관리자만** 본다. 구글 OAuth 없이 가는 방식(사용자 확정 — "로그인 없이 판별"):

- **식별 = localStorage uuid 토큰** (`ta-feedback-token`, 첫 전송 때 생성 —
  일반 방문자에겐 안 만들고 네트워크도 안 쓴다). INSERT에 `author_token`으로 실리고,
  조회는 요청 헤더 `x-feedback-token`이 일치하는 행만 RLS가 돌려준다
  ([supabase-feedback-board.sql](supabase-feedback-board.sql) — dev_notes의 x-admin-key와
  같은 헤더 검사 패턴. Supabase CORS는 커스텀 헤더를 반사 허용, 실측 2026-08-17).
- **답변**은 `feedback_replies` 테이블 — 읽기는 그 제안의 작성자(토큰)만, 쓰기·삭제는
  x-admin-key(/admin → admin-api 프록시, 테이블명 정규식만 검사하므로 워커 수정 불필요).
- **본인 수정·삭제** 가능 (사용자 요청 2026-08-17) — 같은 토큰 정책의 UPDATE/DELETE.
  ⚠ RLS 불일치는 에러가 아니라 **0행 처리 + 200**이므로 클라이언트가
  `return=representation`으로 행 수를 세서 실패 판정한다 (adminWrite와 같은 함정).
  삭제 시 답변은 cascade, 첨부 이미지는 R2에 남는다(/admin 파일 탭에서 정리).
- **열람 코드 = 토큰 그 자체.** 게시판 하단에 노출·복사되고, 다른 기기에서 붙여넣으면
  같은 목록을 이어본다(기기 간 이동 해결). 코드를 적용하면 기존 토큰이 교체되므로 UI가
  경고를 띄운다. 토큰 분실 시 그 스레드는 본인만 못 보게 된다(행은 /admin에 남음).
- **새 답변 뱃지**: 마지막으로 게시판을 연 시각(`ta-feedback-seen`) 이후의 답변 수를
  FAB·모바일 헤더 버튼에 표시 (토큰 보유자만 마운트 시 1회 조회).
- **개발자 코멘트(dev_notes)는 게시판의 공개 탭** (사용자 지시 2026-08-17: "업데이트
  내역의 개발자코멘트를 없애고 여기다가, 모두가 볼 수 있도록") — 업데이트 내역 모달의
  코멘트 뷰는 제거됐고, `#devnotes` 딥링크는 게시판이 이어받는다 (배포된 changelog 행의
  href가 살아 있어야 함). 편집은 종전대로 /admin '개발자 코멘트' 탭.
- **목록 클릭 = 창모달** (사용자 지시 2026-08-17: "높이가 휙 늘어나지 말고 모달창 하나 더")
  — 제안 스레드·개발자 코멘트 모두 인라인 확장 없이 두 번째 ModalWindow로 연다.
- **게시판 관리자 모드** (사용자 확정 2026-08-17: "admin페이지 말고 제안 모달에서 답변 +
  어차피 싹 다 볼 수 있어야") — '다른 기기에서 이어보기' 입력칸에 **관리자 키**
  (.supabase-admin-key 내용)를 넣으면 잠금 해제: 전체 제안 목록(기본은 **대응완료 가림**,
  /admin과 같은 감각) + 스레드 모달에서 답변 등록·삭제·**제안 삭제**·**대응완료 토글**.
  새로고침 ↻는 양쪽 모드 공통. 키는 그 브라우저 localStorage(`ta-feedback-admin`)에 남아
  x-admin-key 헤더로 Supabase REST에 직접 실린다 (틀린 키는 열람 코드 형식 오류와 같은
  문구 — 존재를 안 드러냄). ⚠ 공개 사이트 localStorage에 키가 놓이므로 **관리자 본인
  기기에서만** 쓸 것 — '관리자 해제'가 키를 지운다. 관리자의 제안 삭제는 첨부 이미지
  R2 정리를 못 하므로(파일 API는 /admin 프록시 전용) 남은 이미지는 /admin 파일 탭에서.
- **과도기 가드**: SQL 적용 전엔 `author_token` 컬럼이 없어 INSERT가 400 — 클라이언트가
  종전 모양(익명)으로 1회 재시도해 제안을 버리지 않는다. 임베드 조회도 400이면 답변 없이
  폴백. 구형 익명 제안(토큰 null)은 게시판에 안 뜨고 /admin에서만 보인다(답변 폼 대신 안내).
- 공채 "추가 예정"(`RECRUIT_PENDING`): pending 플래그 → 조합 결과에 "추가 예정" 배지.
  실제 적용되면 `RECRUIT_SUPPLEMENT`로 옮기거나 데이터마인 반영을 기다린다.

### 관리자 페이지 분리 + Cloudflare Access 구글 SSO (2026-07-27, 사용자 확정)

CRUD가 늘며 위험해진 /admin을 본사이트에서 떼어냈다. **비밀번호 게이트는 없다.**

- **admin.terra-archive.net** (Pages 프로젝트 `terra-archive-admin`, `scripts/deploy-admin.sh`) —
  같은 빌드 산출물에서 /admin이 입구. 본사이트 deploy.sh는 admin.html/.rsc를 지우고
  옛 주소를 301로 넘긴다. 도메인 전체를 **Cloudflare Access(Zero Trust, 구글 SSO,
  nzkonaru@gmail.com만 허용)** 가 막는다.
  - ⚠ **문지기는 로그인 방식이 아니라 정책의 Include 규칙이다** (2026-08-15 사용자 발견:
    "아무 구글 계정으로 로그인해도 그냥 들어가진다"). Access는 ① 인증(그 계정의 주인이
    맞나) ② 정책(그 신원을 들여보낼까) 두 단계인데, ②에 조건이 없으면 **구글이든 OTP든
    전원 통과**한다. 이 문서에 '……만 허용'이라고 적혀 있어도 대시보드에 실제로 걸려
    있지 않으면 아무 의미가 없다 — 2026-07-29 정책 키가 `admin` 플레이스홀더로 되돌아간
    사고와 같은 계열(설정이 문서와 어긋난 채 조용히 열려 있는 것)이다.
    **정본 설정**: Zero Trust → Access → Applications → `admin.terra-archive.net` →
    Policies → **Include: Emails = `nzkonaru@gmail.com`**.
    **확인법**: 시크릿 창에서 다른 구글 계정으로 접속 → Cloudflare 차단 페이지가 떠야
    한다(관리자 HTML·JS가 아예 전달되지 않음). 게이트 화면이 보이면 ②가 여전히 열려 있는
    것이다. 로그인 방식(구글/OTP)은 취향 문제이고 보안 차이가 없다.
  - 정책이 열려 있어도 **데이터는 admin-api 워커의 `ALLOWED_EMAIL` 검사(아래)가 2차로
    막는다** — 위 사고 기간에도 남이 본 것은 빈 껍데기 UI뿐이었다. 이 이중 방어를 없애지 말 것.
  - ⚠ Access는 **커스텀 도메인에만** 걸린다 — Pages 프로젝트 기본 주소
    (`terra-archive-admin.pages.dev`)는 덮이지 않는다. `/api/*` 라우트가 안 걸려 데이터는
    못 보지만 UI 껍데기는 열리므로, Access 앱의 도메인 목록에 함께 넣어 두는 게 깔끔하다.
  **배포는 본사이트와 완전히 분리 (2026-07-28 사용자 확정 — 한때 deploy.sh 끝에서 함께
  돌렸으나 되돌림)**: `bash scripts/deploy-admin.sh`는 스스로 빌드하는 단독 명령이고
  (방금 빌드했으면 `SKIP_BUILD=1`), **관리자 UI를 고쳤을 때만** 돌린다. 데이터 갱신·본사이트
  변경 배포에는 관리자가 따라 나가지 않는다 — GitHub Actions 무인 파이프라인도 마찬가지
  (`deploy.sh`만 호출하므로 본사이트만 갱신). 관리자 화면 내용 대부분은 Supabase에서
  읽으므로 데이터 배포와 무관하다.
- **admin-api 프록시 워커** ([workers/admin-api](../workers/admin-api/), 라우트
  `admin.terra-archive.net/api/*`) — Access JWT(RS256, 팀 JWKS)를 검증한 뒤에야
  관리자 키를 붙여 중계: `/api/supabase/<table>` → Supabase REST(+`x-admin-key`),
  `/api/files…` → 업로드 워커(+`x-admin-key`), `/api/me` = 로그인 확인.
  **브라우저에는 어떤 관리자 키도 없다.** `workers_dev = false`(Access 우회 경로 차단),
  ACCESS_TEAM/AUD 미설정이면 503 거부가 기본값.
- 프론트 규약: 모든 admin CRUD는 같은 오리진 **`/api`** 상대경로(`ADMIN_REST` 등,
  feedback.ts) — Access 쿠키가 자동 동반된다.
- **로컬 개발**: dev 서버 전용 vite 플러그인(`scripts/admin-dev-proxy.ts`)이 `/api/*`를
  가로채 레포 루트 키 파일(`.supabase-admin-key`·`.upload-admin-key` — gitignore)로
  직접 중계한다 → localhost:3000/admin이 실서비스와 동일하게 동작. 키 파일이 없는
  기기에서는 503 + 게이트 안내. 빌드 산출물에는 포함되지 않는다(`apply: "serve"`).
- **키 회전**: `node scripts/make-admin-rotate-sql.mjs` → `.supabase-admin-key`(gitignore) +
  `.admin-rotate.generated.sql`(Supabase SQL Editor에서 실행) → admin-api 워커 시크릿
  `SUPABASE_ADMIN_KEY`/`UPLOAD_ADMIN_KEY` 갱신. 옛 키('admin')는 SQL 문서에 평문
  커밋돼 있었으므로 **Access가 동작 확인된 직후 반드시 회전**한다.

### 업데이트 내역 — DB 원장 (2026-07-27, 사용자 확정)

헤더 로고 오른쪽 🛠 버튼 모달. **내용은 코드에 두지 않는다** — "매번 빌드해서 올리지 말고,
디비에 저장하면 자동으로 나오게" (사용자 지시). 새 항목은 `/admin` → **업데이트 내역** 탭에서
넣으면 **배포 없이 즉시** 사이트에 뜬다.

- 테이블: `public.changelog` — 스키마·RLS·시드 [supabase-changelog.sql](supabase-changelog.sql).
  열: `released_at`(날짜) · `kind` · `area` · `ko`/`en`/`ja` · `href`(바로가기, 선택) · `seq`(같은 날짜 정렬).
- 종류 5종: `new`(신기능) · `improve`(개선) · `change`(수정) · `fix`(버그 수정) · `data`(데이터 갱신).
  **`change`와 `fix`는 별개다** (사용자 확정 2026-07-27) — 이름 정리·문구 교체처럼 버그가 아닌
  일반 변경은 `change`, 실제 오작동을 고친 것만 `fix`.
- **영역 8종** `area` (사용자 요청 2026-07-29 "인프라 개선 / 사이트 개선처럼 나누자"):
  `infra` · `archive` · `recruit` · `farm` · `upgrade` · `story` · `rogue` · `site`.
  배지가 **'{영역} {종류}'** 로 읽힌다 — 어순이 로케일마다 달라 `"{area} {kind}"` 서식 키로 조립
  (EN은 `Base · Improved`처럼 가운뎃점). 비면 `href`로 유추하고(`areaOf`) 그래도 모르면 `site`.
  - 조회는 **`select=*`** 다 — `area` 컬럼 마이그레이션 전에도 400이 나지 않게 (없는 컬럼을
    명시하면 PostgREST가 400을 내고 모달 전체가 안 뜬다).
  - 옛 행 백필: `node scripts/changelog-backfill-area.mjs [--write]` (alter table 실행 후).
  - 배지 폭은 CSS에서 38%로 묶는다 — EN 라벨이 길어(`Integrated Strategies · Improved` 190px)
    좁은 화면에서 본문 칸을 절반 넘게 먹고 행 높이가 41→102px로 튀었다(실측 390px).
- **3개 언어를 행에 함께 저장**한다. `en`/`ja`가 비면 프론트가 `ko`로 폴백하고,
  관리자 목록엔 "번역 미완" 칩이 붙는다 — i18n 사전(app/i18n.tsx)에는 **UI 라벨만** 둔다.
- **정렬** (사용자 확정 2026-07-29): 날짜 최신순 → 같은 날짜 안에서 **① 신기능(`new`)이 맨 위
  ② 나머지는 최신 등록순**. 이 배치는 `seq`(작을수록 위) 값으로 표현한다 —
  새 항목을 넣었으면 그날 것들의 seq를 다시 매겨야 맨 위로 온다
  (일괄 재정렬: `scripts/`가 아니라 1회성 스크립트로 처리, 규칙은 위 두 줄이 정본).
  조회 정렬에 `created_at.desc`가 마지막 기준으로 붙어 있어, seq가 겹쳐도 나중 것이 위로 온다.
- 표시 규칙 (사용자 확정 2026-07-27) — **종류 필터와 기간 확장은 별개 축**이다:
  - 종류: 기본은 **신기능(`new`)만**. '상세보기'를 눌러야 개선·버그 수정·데이터 갱신까지 보인다
    (이미 받아둔 행을 거르는 것이라 **재요청 없음**).
  - 기간: 최근 7일치로 시작해 '지난 기록'을 누를 때마다 **7일 창을 하나씩 과거로** 이어 붙인다
    (무한). 창이 비면 자동으로 다음 창까지 넘어가 클릭이 헛돌지 않게 한다(최대 80창 가드).
    남은 게 있는지는 첫 로드 때 함께 받아둔 **전체 최고령 날짜**로 판정하고, 소진되면 버튼을 감춘다.
  - 항목 길이: 기본은 **핵심 한 줄만**, 끝의 '상세보기'를 눌러야 나머지가 펼쳐진다
    (사용자 요청 2026-07-29 "줄줄줄줄 너무 길어지니까"). 가르는 자리는 집필 관례인 `" — "`
    앞 — 실측 28행 중 KO 85%·EN 82%가 이 형식이고 **80자 넘는 항목은 3개 언어 모두 예외 없이**
    이 구분자를 갖는다. 없으면 첫 문장에서 자른다(`splitChange`). 일본어 `。`는 **뒤에 공백이
    없으므로** 문장 끝 정규식에서 공백을 요구하면 안 된다 — 요구했더니 JA가 하나도 안 접혔다.
  - 위 두 '상세보기'는 **축이 다르다**: 헤더 것은 어떤 종류를 목록에 낼지, 항목 안의 것은
    그 항목의 뒷부분을 펼칠지.
  - **`fix`(버그 수정)는 한 줄로 끝낸다** (사용자 확정 2026-07-31: "너무 자세하게 적지 말자
    솔직히 좀 부끄러움. 그냥 이런 버그가 있었는데 고쳤다 까지만"). **"어디서 무엇이
    잘못됐는데 고쳤다"** 한 문장만 쓰고, 원인·내부 구조·재현 수치·재발 방지는 적지 않는다
    → `" — "`도 쓰지 말 것(접힘이 생기면 그만큼 길게 썼다는 뜻이다). 다른 종류(`new`·`improve`)는
    기존대로 머리글 + 접힘 상세를 써도 된다.
- 읽기는 anon 공개(`using (true)`), 쓰기·수정·삭제는 `x-admin-key` 헤더로만.
- 프론트: `app/changelog-api.ts`(조회·관리자 CRUD) + `app/changelog.tsx`(버튼·모달).

### 팁 풍선 — 떠다니는 힌트 (2026-07-27, 사용자 확정)

화면 빈 곳을 찾아 옮겨 다니는 힌트 풍선. 사용자 요구: **한곳에 고정 금지 · 본문을 가리면 안 됨 ·

**팁 풍선** 탭에서 넣으면 배포 없이 반영된다.

- 테이블: `public.tips` — [supabase-tips.sql](supabase-tips.sql). 열: `title_{ko,en,ja}` ·
  `body_{ko,en,ja}` · `image` / `image_dark` · `href` · `active` · `seq`.
  번역이 비면 프론트가 ko로 폴백(관리자 목록에 "번역 미완" 칩).
- **가리지 않는 방법** (`app/tip-balloon.tsx`): 화면을 9×7 격자 후보로 나눠, 후보마다 풍선 크기
  사각형의 **9점을 `elementFromPoint`로 찍어** 글자·이미지·버튼·배경/테두리 있는 카드가 하나라도
  걸리면 버린다. 남은 후보 중 화면 중앙(본문)에서 멀고 직전 자리에서 먼 쪽을 무작위로 고른다.
- 자리 유지: 2.5초 감시 타이머가 현재 자리를 다시 검사해 스크롤·탭 전환으로 더럽혀지면 즉시 옮기고,
  17초마다 자리를 옮기며 다음 팁으로 넘어간다. **마우스를 올려두면 움직이지 않는다**(클릭하려는데
  도망가지 않게). 모달(`.modal-backdrop`)이 열려 있으면 스스로 숨는다.
- 펼침: 카드 높이는 내용마다 달라 상수로 가둘 수 없다 — `useLayoutEffect`가 실측해 화면 밖으로
  나간 만큼 `transform`으로 되민다(transition 목록에 없어 즉시 보정).
- 빈 자리가 없으면(좁은 화면 등) 그냥 표시하지 않는다. '팁 그만 보기'는 localStorage에 12시간 저장.
  조회 실패(테이블 미설치 포함)도 조용히 숨긴다.

### 파일 저장소 — Cloudflare R2 (2026-07-27, 사용자 확정)

팁 이미지처럼 "배포 없이 넣는 콘텐츠"가 쓸 파일의 저장소. S3류 후보 중 **R2로 확정**
(같은 Cloudflare 계정 + 이그레스 무료 + 무료 10GB). 사용자 혼자 올리고 사이트가 공개 URL로 쓴다.

- 버킷: `terra-archive-files` · 앞단 워커: [workers/upload](../workers/upload/) (`terra-archive-upload`).
  업로드·목록·삭제(`/files…`)는 `x-admin-key` 헤더가 **`ADMIN_KEY` 시크릿**(= /admin 입장
  비밀번호) 또는 **`SYNC_KEY`**(에셋 동기화 전용 무작위 키, 레포 루트 `.r2-sync-key` —
  gitignore)와 일치할 때만. 공개 서빙은 커스텀 도메인이 담당(워커 `GET /f/<key>`는 폴백).
- **버킷 구조 (2026-07-27)**: `uploads/`(수동 업로드) · `assets/`(사이트 에셋 — r2-sync 관할)
  두 갈래. admin 키의 **쓰기·삭제는 `uploads/` 안으로 강제**(에셋 트리 실수 삭제 방지 —
  워커가 403), sync 키만 전체를 만진다. 목록은 둘 다 전체 — /admin 파일 탭이
  **내 업로드 / 사이트 에셋** 두 하위 탭으로 나눠 보여준다(에셋은 폴더 트리 + 검색,
  업로드도 검색). 수동 업로드 URL은 `https://files.terra-archive.net/uploads/<이름>`.
- 프론트: `app/files-api.ts`. `/admin` → **파일** 탭에서 드래그/선택 업로드 → URL 복사,
  팁 편집기 이미지칸 옆 **올리기** 버튼은 올리자마자 URL을 칸에 채운다.
- **같은 이름은 덮어쓴다** — 공개 URL 캐시 때문에 반영이 늦을 수 있다(이미지 30일·JSON 1일).
  키는 `safeKey()`가 정리(NFC 정규화 — macOS 한글 파일명은 자모 분리형이라 필수).
- 워커 배포·시크릿: `cd workers/upload && bash deploy.sh`,
  `npx wrangler secret put ADMIN_KEY`. R2는 대시보드에서 최초 1회 활성화 필요.

### 정적 에셋 전체 R2 이관 (2026-07-27, 사용자 확정 "싹 다 옮겨줘")

public/의 대용량 폴더 **story·rogue·lens·tesseract·avatars·about·og·items·scan**
(334MB/7,744파일)과 상세 모달 지연 로딩 데이터 **profiles·skins·skin·voice·skills**는
Pages가 아니라 **R2 버킷 커스텀 도메인 `files.terra-archive.net`**
(요청 수 무제한 · CDN 캐시 · 워커 경유 없음)에서 서빙한다.
사이트 배포가 **7,859개/423MB → 115개/26MB**로 줄어든 이유의 전부.

- **경로 규약**: 데이터 JSON·내부 상태에는 종전대로 루트 상대경로(`/avatars/…`)를 두고,
  `<img src>`·`fetch()`·tesseract 경로처럼 **요청이 나가는 경계에서만 `asset()`**
  (`app/assets.ts`)으로 감싼다. 데이터 재생성 파이프라인은 손대지 않는다.
- **동기화**: public/에 파일은 그대로 두고(파이프라인·git 유지) `node scripts/r2-sync.mjs`가
  **`assets/<public 상대경로>`** 키로 md5↔etag 증분 업로드. `deploy.sh`가 배포 전에 자동
  실행(키 없으면 경고 후 스킵 — GH Actions는 `R2_SYNC_KEY` 시크릿 등록 시 활성화).
  `--prune`은 로컬에 없는 assets/ 원격 키를 지운다(uploads/는 절대 안 건드림).
  **안전장치**: 원격엔 있는데 로컬이 빈 폴더가 있거나 삭제량이 원격의 10%를 넘으면 삭제를
  건너뛴다 — 빌드가 중간에 죽어 출력 폴더가 비었을 때 R2가 지워지는 것을 막는다
  (2026-08-01, scripts/README.md §8). 진짜 대량 정리는 `--prune --force`.
  캐시 정책은 확장자별(이미지·엔진 30일, **json/txt/bin은 60초 + must-revalidate**).
  ⚠ 데이터 파일은 이름이 그대로인 채 내용만 바뀌어 URL이 캐시 무효화의 계기가 되지 못한다.
  옛 값 `max-age=86400`은 "갱신 후 최대 하루 동안 옛 데이터"를 뜻했고 2026-08-02에 실제로
  당했다(이격 안젤리나 S2 레벨별 수치가 "다시 안 바뀌는 상태로 돌아갔다" — R2·배포본은
  정상이고 브라우저 캐시만 옛것). 정책을 바꿔도 **이미 올라간 오브젝트의 메타데이터는
  안 바뀌므로** `node scripts/r2-sync.mjs --recache`로 한 번 다시 씌워야 한다.
- **안전망**: deploy.sh가 스테이징에서 위 폴더를 지우고 `_redirects`(301→R2)를 깐다.
  ⚠ `/rogue`·`/about`은 **페이지 경로와 겹치므로 통짜 와일드카드 금지** — Pages splat은
  빈 문자열에도 매치되어 페이지를 삼킨다. rogue는 하위 폴더별로만, about은 코드 전환으로만.
- **CORS 함정 (실측)**: 같은 URL을 `<img>`(Origin 없음)로 먼저 받으면 무-ACAO 응답이
  브라우저 캐시(30일)에 남아, 이후 `crossOrigin` 캔버스 로드가 CORS로 죽는다.
  캔버스용 로드는 **`?cors` 쿼리로 캐시 키를 분리**한다 (planner 편성 이미지 저장).
  tesseract.js v5는 워커를 blob으로 만들어 크로스 오리진에서도 동작한다(버킷 CORS GET/HEAD *).
- 검증: 스크래치패드 verify-r2 하네스 16항목(그리드·스토리 전문·OCR 예열·캔버스 픽셀
  읽기·/about 페이지 생존 등) — lazy 이미지는 `complete`만 세야 오탐이 없다.

### 데이터가 나가는 두 경로 — 번들(배포) vs R2(동기화) (2026-08-02 정리)

"뭐는 배포해야 하고 뭐는 안 해도 되는지" 헷갈리는 지점. 기준은 **데이터냐 에셋이냐가 아니라
"첫 화면에 필요하냐, 열어볼 때만 필요하냐"** 이다.

| | 위치 | 실리는 방식 | 반영 조건 | 규모 |
|---|---|---|---|---|
| **번들** | `app/data/*.json` (git) | 코드가 `import` → 빌드 때 JS 청크에 박힘 | **배포해야 반영** | 26MB · 115파일 |
| **R2** | `public/` 밑 14개 폴더 | `asset()`으로 URL 만들어 `fetch` | **r2-sync만 하면 반영** | 767MB · 15,300파일 |

- 번들: `operators.json`(+`.en`/`.ja`), `costs`·`infra`·`farm`·`recruit`·`rogue1~6`·`stories`·
  `broadcasts`·`story-summaries` — 목록·검색·플래너 계산처럼 **화면을 그리는 순간 필요한 것**.
- R2: `avatars`·`skills`·`profiles`·`voice`·`skins`·`skin`·`modules`·`records` (오퍼당 파일 1개씩) +
  `story`·`rogue` 이미지/스크립트·`lens`/`tesseract` OCR·`items`·`scan`·`about`·`og` —
  전부 **상세 모달이나 스토리 화면을 열 때만** 받아온다.

**신규 오퍼 1명은 양쪽을 다 건드린다.** git 쪽은 `operators.json` ×3언어 + costs·infra·farm·
recruit, R2 쪽은 `avatars/<id>.webp` 1개와 `{skills,profiles,voice,skins}/{ko,en,ja}/<id>.json`
12개. 한쪽만 돌면 반쪽이 된다 — 배포만 하고 동기화를 빼먹으면 **오퍼는 뜨는데 섬네일·스킬
레벨·프로필·보이스가 전부 404**다 (2026-08-01 실제 발생: CI에 `R2_SYNC_KEY`가 없었다).

실무상 고를 일은 없다 — **`bash scripts/deploy.sh` 하나가 빌드→r2-sync→Pages 업로드를 다 한다.**
무인 파이프라인도 같은 스크립트를 쓴다. 어긋남을 막는 장치는 둘:

- `scripts/audit-assets.mjs` (ci-refresh rest 단계) — 아바타 누락, 스킬이 있는데 레벨 파일이
  없는 오퍼, **로케일 일부에만 있는 파일**, `--r2`면 R2 미동기 건수까지 본다. 정상적인 공백
  (스킬 0개 로봇·핸드북 없는 예비 오퍼레이터)은 데이터에서 유도해 걸러내므로 기준선 파일이 없다.
- `deploy.sh`는 R2 키가 없으면 **빌드도 하기 전에 exit 1** — 예전엔 경고만 찍고 넘어가서
  아무도 안 읽었다. 코드만 고쳤을 때만 `--skip-r2`.

**미실장(CN 선행) 오퍼가 한섭에 실장되면** 손으로 갈아끼울 것은 없다.
`regen-operators.py`의 미래시 패스가 `if cid in chars: continue`로 KR 테이블에 생긴 오퍼를
건너뛰므로, 1차 패스가 만든 공식 한국어 데이터가 그대로 이긴다. 다만 인프라·비용·파밍은
그때 **다시 돌아야 한다** — 미실장 동안 쓰던 CN 폴백 + AI 번역이 공식 텍스트로 교체되어야
하고, 실장 오퍼의 시너지 판정이 미실장 오퍼 이름을 키로 쓰고 있기 때문이다
(`build-infra.py`의 파트너 탐지). 이것도 `data-refresh.yml`이 자동으로 처리한다.

### 죽은 청크(stale chunk) — "Failed to fetch dynamically imported module"

`npm run build`를 돌리면 `dist/assets/index-<해시>.js` 의 해시가 바뀌므로, **그전에 열어 둔
탭**(localhost:3000이든 배포본이든)이 물고 있던 청크 URL이 404가 되고 지연 로딩 컴포넌트
(스캐너 모달·렌즈 도움말)가 `Failed to fetch dynamically imported module`로 터진다.
개발 중 빌드할 때마다, 그리고 실사용자가 배포 직후 오래된 탭에서 이동할 때 똑같이 난다.

원인이 두 가지이고 **대응이 다르다** (2026-07-25 실측으로 구분):

1. **탭이 낡은 경우** (배포 직후 오래된 탭, 서버는 새 HTML을 내보냄) → `app/layout.tsx`의 인라인
   스크립트가 `vite:preloadError`·청크 로드 실패를 잡아 **한 번만** 새로고침해 자동 복구한다
   (10초 가드로 루프 방지).
2. **서버가 낡은 경우** — `npm run start`(`vinext start`)를 **띄워 둔 채 재빌드**하면, 그 프로세스는
   시작 시점의 번들을 물고 있어 **옛 해시를 가리키는 HTML을 계속 내보낸다**. 이러면 새로고침해도
   낫지 않는다(자동 복구 스크립트도 낡은 HTML에는 없다). 확인법:
   `curl -s localhost:3000/ | grep -o 'assets/index-[^"]*\.js'` 와 `dist/client/index.html`의 해시가
   다르면 이 경우다. **해결은 서버 재시작뿐** — ⌃C 후 `npm run start`.
   작업 중 미리보기를 계속 볼 거면 `npm run dev`(HMR)로 띄우는 편이 낫다.

세션 중 빌드 확인을 한 뒤에는 이 2번이 흔하다 — 빌드했으면 **미리보기 서버를 재시작**할 것.
