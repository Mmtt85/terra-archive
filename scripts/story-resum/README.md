## 3. 한 편을 처리하는 절차 (명령 그대로)

```bash
cd /Users/byeonghoseong/Documents/workspace/terra-archive
S=scripts/story-resum
```

**① 준비** (새 세션이면 남은 큐 전체를 한 번에): `python3 $S/prep.py <id> [<id> …]`

**② 집필 에이전트 띄우기** — Agent 도구, `model: "opus"`, `run_in_background: true`. 프롬프트:

> 이벤트 id **<id>** 「<한국어 이름>」의 스토리 요약을 새로 써 줘. 지시서 `/Users/byeonghoseong/Documents/workspace/terra-archive/scripts/story-resum/PROMPT.md` 를 먼저 끝까지 읽고 그대로 따른다 (<id> = <id>). 특히 3-1(장면 전환 이음말)·3-2(원인·결과 문장 엮기)·5-1(배경 삽화)·6(카드) 규칙을 놓치지 말 것.

한국어 이름은 `app/data/stories.json` 의 `events[].name.ko`.

**③ 끝나면 점검·병합** (에이전트 보고를 읽고, 경고가 있으면 out 을 보고 판단):

```bash
python3 $S/merge.py <id> && python3 scripts/measure-story-images.py >/dev/null \
  && python3 scripts/story-i18n-setup.py >/dev/null 2>&1 && echo <id> >> $S/done.txt
```

- `⚠ 3문장 초과 N` 은 대개 문단 끝 인용 대사까지 센 것이라 그대로 둬도 된다(눈으로 한 번 본다).
- `measure-story-images.py` 는 **반드시** 돈다 — 배경 그림(`/story/bg/`)의 크기를 `story-image-dims.json` 에 넣는다(안 하면 그림 자리가 출렁인다).
- 에이전트 보고에서 **카드**를 꼭 본다: 정체가 반전인 인물의 정체가 desc·alias 에 들어갔으면 빼고, 세계관 기본어(테라·로도스 아일랜드·용문·우르수스·카즈델·시라쿠사·라테라노·산크타 …) 용어 카드는 뺀다. op 를 달 수 있는데 안 단 인물은 `operators.json` 이름으로 찾아 단다.

**④ 번역 에이전트 띄우기** — 같은 방식(opus, 배경). 프롬프트:

> 스토리 요약 id **<id>** 「<이름>」을 영어·일본어로 번역해 줘. 지시서 `/Users/byeonghoseong/Documents/workspace/terra-archive/scripts/story-resum/TPROMPT.md` 를 먼저 끝까지 읽고 그대로 따른다.
>
> 한국어 본문은 <문체 설명> — <말투 지시>. 고유명사(<이 이벤트 주요 인물·지명 몇 개>)는 공식 영어·일본어 대본(로컬 `.gamedata/story-cache` 의 en__/jp__ 파일)과 operators.{en,ja}.json 표기로 맞춘다.

말투 지시: 무거움이면 "무거운 이벤트의 평서체 '~다'에 농담이 전혀 없다 — 영어는 담담하고 무게 있는 평서(plain/somber), 일본어는 だ・である調로". 중간이면 "해요체이고 앞부분은 농담을 섞었지만 N장부터는 농담을 끄고 가라앉는다 — 영어는 친근한 톤으로 시작해 뒷부분은 담담하게, 일본어는 です・ます調를 유지하되 뒷부분은 농담 없이". 밝음이면 "해요체 코미디 — 영어 친근체, 일본어 です・ます調".

**⑤ 번역이 끝나면 발행:**

```bash
python3 scripts/story-i18n-merge.py --publish 2>&1 | grep -E '^\[|✗'
```

`✗ <id> (KO 폴백)` 으로 남는 것은 **번역이 아직 안 끝난 편**뿐이어야 한다 (한국어 본문이 새로 써져서 옛 번역과 블록 수가 안 맞으므로, 번역이 끝날 때까지 EN/JA 화면에 한국어가 나온다 — dev 에서는 괜찮다).

**⑥ 다음 편** — `queue.txt` 에서 `done.txt` 에 없는 첫 id 로 ②.

## 4. 운영 요령·함정

- **동시 집필 4편 + 번역** 이 적당하다. 집필 한 편 15~30분(원문 28만 자짜리는 27분), 번역 10~15분. 하위 에이전트 한 편이 20만~65만 토큰을 쓴다.
- **세션 사용량 한도**에 걸리면(HTTP 429) 에이전트가 중간에 죽는다. 한도가 풀린 뒤 **SendMessage 로 그 에이전트에게 "이어서 끝내라"** 를 보내면 대화 기록에서 이어 간다(2026-10-04 02:07 다섯 개가 죽었고 10:50에 이렇게 살렸다). 새로 띄우면 처음부터 다시 읽는다.
- **번역 에이전트가 돌리는 merge 는 `--publish` 없이도 `app/data/story-summaries.{en,ja}.json` 을 쓴다** — 이미 발행된 번역이 바뀌지 않으면 '중단' 없이 그대로 쓰는 설계다. 에이전트가 "말하지 않은 파일을 썼다"고 보고해도 정상이다.
- **한국어 공식 대본의 오역**을 번역 에이전트가 잡아 올 때가 있다(바벨: "길에 나뒹구는 머리" ← 원문 攒动的人头 = 붐비는 인파, 공식 EN/JP 도 붐비는 거리). 그러면 한국어 요약도 원뜻으로 고치고, en/ja 파일의 `_ko` 지문을 지운 뒤 merge 를 다시 돌린다.
- 기존 사이트 카드에 사실 오류가 꽤 있었다(로사/레토 본명 뒤바뀜, 니엔을 슈의 '남동생', 테레시스를 '쌍둥이 동생', 행운의 아내 사망 단정 …). 에이전트가 원문으로 바로잡으니 보고의 '고친 것'을 사용자 보고에 옮긴다.
- **그림 경로는 대소문자까지 실제 파일 이름이어야 한다** — 원문은 `23_I01` 처럼 대문자인데 파일은 `23_i01.webp` 다. macOS 는 대소문자를 안 가려서
  dev 에선 보이지만 라이브(R2)는 404 다 (2026-10-04 니어 라이트 12장·루센트 애로우헤드·불로 비춰주소서 1장씩, 고쳐 둠). prep.py 가 `[CG: …]` 를
  실제 이름으로 적고, merge.py 가 대소문자까지 검사한다.
- 보고는 **한국어로만**, 편마다 짧게: 분위기 판정(애매했으면 무엇과 무엇 사이), 분량·삽화(컷씬/배경), 카드 변경, 원문 대조로 고친 것.

- 배포 뒤 업데이트 내역(changelog-post 스킬)은 사용자가 원할 때 — 하루치로 묶어 "스토리 요약 N편 새로 집필" 한 건.
