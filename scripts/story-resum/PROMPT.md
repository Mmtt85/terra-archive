## 할 일
이벤트 하나의 'AI 스토리 요약'을 **처음부터 새로** 쓴다. 기존 요약을 고치는 게 아니다.

1. 집필 규칙 두 파일을 **끝까지** 읽는다: `.claude/skills/story-summary/SKILL.md`, `.claude/skills/story-summary/WRITING-GUIDE.md` (저장소 기준 경로). 문체·구조·컷씬·감정선·생사 대조·메타 멘트 금지 규칙을 그대로 따른다.
2. 원문 `src/<id>.txt` 를 **처음부터 끝까지 전부 정독**한다 (대사·나레이션·자막·선택지·CG 위치를 에피소드 순서대로 평문화한 것. 나눠 읽되 건너뛰지 말 것). 에피소드마다 노트를 남긴다. `src/<id>.meta.json` 의 `src` 가 "cn" 이면 원문은 중국 서버 스크립트를 사이트가 한국어로 옮긴 번역본이다 — 인물·지명 표기는 그 번역본을 따른다.
3. 다 읽은 뒤 **분위기 분류**(WRITING-GUIDE §2)를 정한다: 무거움 → 평서체 '~다' + 위트·농담 일절 금지 / 밝음 → 해요체 + 농담 / 중간 → 해요체 + 후반 감정 구간에서 농담을 끈다. 몸통이 어두우면 무거움. 한 이벤트 안에서 문체를 섞지 않는다. tagline 도 같은 결.
3-1. **장면 전환 이음말**: 다른 장소·인물·시간으로 넘어가는 문단 첫 문장에는 '그리고', '한편', '그 무렵', '같은 시각', '며칠 뒤', '그사이' 같은 이음말을 둔다(WRITING-GUIDE §2). 없으면 장면이 뚝 끊긴다 — '~다' 문체에서 특히. 같은 장면 안의 문장마다 붙이지는 않는다.
3-2. **이어지는 행동·인과는 한 문장으로**: 같은 인물의 연속 동작이나 '~해서 ~했다'로 묶이는 원인·결과를 마침표로 잘게 끊지 말고 '~했고', '~해서', '~하자'로 엮는다(WRITING-GUIDE §2). ✗ "조야는 집 근처까지 온다. 그곳에서 발레리를 만난다." → ✓ "조야는 집 근처까지 왔고, 그곳에서 발레리를 만난다." 짧은 문장은 충격·여백이 필요한 자리에만.
4. 분량: blocks 의 x + cap 합산이 `src/<id>.meta.json` 의 `target` 범위 안 (파이썬으로 실측).
5. 컷씬: 원문에 `[CG: 이름]` 으로 표시된 그림만 `{"t":"img","src":"/story/cut/<이름>.webp","cap":"캡션"}` 으로 쓴다("(사이트에 그림 없음)" 표시가 붙은 것은 쓰지 않는다). 그 장면을 서술하는 문단 옆에 둔다.
5-1. **배경 삽화** (사용자 요청 2026-10-04 "삽화가 너무 적다"): 원문에 `[배경: 이름]` 으로 표시된 배경 그림(장면이 바뀔 때 게임이 까는 배경)도 `{"t":"img","src":"/story/bg/<이름>.webp","cap":"캡션"}` 으로 쓸 수 있다. 컷씬과 합쳐 **챕터당 한 장 안팎**이 되도록, 컷씬이 없는 챕터를 중심으로 보탠다(컷씬이 넉넉하면 안 써도 된다). 그 배경이 실제로 깔린 장면을 서술하는 문단 바로 뒤에 둔다. 같은 배경을 두 번 쓰지 않고, 검은 화면·흰 화면처럼 그림이 없는 배경은 표시되지 않는다. 캡션은 그 장소·장면을 원문이 확인해 주는 만큼만 쓴다(장소 이름을 모르면 장면으로 쓴다).
6. 인물·용어 카드(chars/terms): `cards/<id>.json` 이 지금 사이트의 카드다. 이것을 출발점으로 —
   - 새 본문에 name 이나 alias 가 한 번도 안 나오는 카드는 뺀다.
   - 새 본문의 주요 인물·처음 보면 모를 고유명사인데 카드가 없으면 더한다 (SKILL.md 의 chars/terms·alias·op 규칙 그대로. op 는 `app/data/operators.json` 에서 이름으로 찾는다. desc 는 스포일러 없이 한 줄, 백과사전식 서술체).
   - 테라·로도스 아일랜드·용문·우르수스·리유니온처럼 **세계관 기본 고유명사는 용어 카드로 만들지 않는다** (팬사이트 독자는 이미 안다 — 밑줄만 늘어난다). 그 이벤트에서 처음 나오는 지명·조직·제도만.
   - 남기는 카드의 desc 는 그대로 둬도 되고, 새 본문과 어긋나면 고친다.
   - **정체가 반전인 인물**(가명·위장으로 나오다 정체가 드러나는 인물)은 카드를 만들지 않거나, 만들더라도 처음 드러난 겉모습만 쓴다 — desc·alias 에 정체를 넣으면 밑줄 툴팁이 스포일러가 된다 (전례: 춘·키야르·클로비시아·트라고디아·케프·크루즈·마르투스·카시아를 뺐다).
   - **기존 요약 본문(app/data/story-summaries*.json 의 blocks·tagline)은 열지도 grep 하지도 않는다** — 새로 쓰는 글이 옛 글에 끌려가지 않게. 카드는 cards 파일만 본다.
7. 집필 후 **인물 생사 대조 패스**(WRITING-GUIDE §7-1)를 원문만 보고 한다. 원문에 없는 사건·대사·후일담, 원문이 단정하지 않은 정체·생사의 단정 금지. 자기 검수 체크리스트(§7)도 확인한다.
8. 출력: `out/<id>.json` 에 `{"tagline": "...", "chars": [...], "terms": [...], "blocks": [...]}` 하나 (UTF-8, ensure_ascii=False). json.load 로 다시 읽어 확인한다.
9. `out/<id>.json`(과 필요하면 `work/<id>/` 의 보조 파일) 말고는 저장소의 어떤 파일도 고치지 않는다. git 도 쓰지 않는다. 다른 하위 에이전트에 위임하지 않는다.

- 구성: 테마의 무대·전제(도입) → 탐험 속에서 드러나는 인물·사건(조우 사건·방문객 기록 중 줄기가 되는 것만 골라 이야기로 엮는다) → **엔딩마다 한 챕터 안팎**(엔딩 대본이 무엇을 보여 주는지, 엔딩 기록이 보탠 사정) → 맺음. 게임 수치·보상·조작 설명은 쓰지 않는다. 조우 사건은 수백 개라 다 옮기지 말고, 테마 이야기의 줄기에 닿는 것만 쓴다.
- 그림: 원문의 `[CG: …]`·`[배경: …]` 에 더해, 맨 끝 **[그림 목록]** 의 `pic_rogue_N_*` 도 `/story/cut/<이름>.webp` 로 쓸 수 있다. 무엇이 그려졌는지 모르면 그 파일(`public/story/cut/<이름>.webp`)을 열어 보고 캡션을 단다. 챕터당 한 장 안팎.
- 카드 desc 는 테마 이야기 기준으로. 엔딩의 반전(정체·생사)은 카드에 넣지 않는다.
