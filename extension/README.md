# 테라 브리지 (실험용 크롬 확장)

게임 창(에뮬레이터 · PC 클라이언트)을 캡처해 테라 아카이브 페이지로 프레임을 보낸다.
**인식은 하지 않는다** — 프레임만 넘기고, OCR·매칭·이동은 전부 사이트(`app/lens/*`)가 한다.
그래서 규칙·데이터가 바뀌어도 이 확장은 갱신할 일이 없다.

## 설치 (개발자 모드, 스토어 등록 전)

1. 크롬에서 `chrome://extensions` 열기
2. 우측 상단 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드합니다** → 이 `extension/` 폴더 선택
4. https://terra-archive.net 열기 (로컬은 http://localhost:3000)
5. 헤더의 **게임 연결** 버튼 → 크롬 피커에서 **창** 탭 → 에뮬레이터 선택

버튼은 이 확장이 깔린 사람 헤더에만 나타난다 — 안 깔린 사람에겐 아무것도 늘지 않는다.

macOS는 첫 캡처 때 시스템 설정 → 개인정보 보호 및 보안 → 화면 기록에서 Chrome을 허용해야 한다.

## 구조

| 파일 | 역할 |
|---|---|
| `background.js` | 서비스 워커. `chooseDesktopMedia`로 창을 고르고 스트림 id만 넘긴다 |
| `content.js` | 페이지 다리 + **캡처 + 변화 게이트** |

메시지 경로: `페이지 ⇄ content.js ⇄ background.js`

### 왜 캡처가 콘텐츠 스크립트에 있나 (2026-07-26 실측)

오프스크린 문서에 두려 했으나 두 제약에 막혔다.

1. MV3 서비스 워커의 `chooseDesktopMedia`는 **대상 탭이 필수**다 —
   `A target tab is required when called from a service worker context`
2. 그렇게 받은 스트림 id는 **그 탭의 렌더러에 묶인다.** 오프스크린 문서에서 소비하면
   `Error starting tab capture`로 실패한다.

그래서 캡처는 사이트 탭과 같은 렌더러인 콘텐츠 스크립트가 맡는다.
대신 탭 스로틀(숨겨진 탭의 타이머는 1초로, 5분 뒤엔 더 심하게 묶인다)을 피하려고
`setInterval`이 아니라 **프레임 구동**으로 돈다 — `MediaStreamTrackProcessor`의
ReadableStream은 프레임이 도착할 때마다 깨어나므로 타이머 스로틀을 받지 않는다.
게임이 브라우저를 완전히 가려도 계속 도는 것이 이 기능의 전제다.

## 변화 게이트

매 프레임 OCR을 돌리면 게임 프레임레이트를 잡아먹는다. 그래서 싼 필터를 앞에 둔다.

1. 도착한 프레임을 400ms 간격으로만 검사한다 (나머지는 즉시 폐기). 64×36 그레이로 줄여 직전 검사와 평균 절대차를 잰다
2. 차이가 크면 = 전투/전환 중 → **버린다**
3. 두 틱 연속 정지 = 화면 안착 → 후보
4. 마지막으로 보낸 화면과 충분히 다를 때만 원본 해상도 프레임 1장을 보낸다

무거운 인식은 "새 화면에 막 도착했을 때" 화면당 1회만 돈다.
헤더 버튼에 마우스를 올리면 `전송 N/M`이 뜬다 — **N ≪ M**이면 게이트가 제 일을 하는 것.

## 지금 재려는 것

`app/scan/scanner.tsx` 주석대로, v6에서 라이브 공유를 접은 이유는 **반해상도**였다.
픽스처를 2배 축소해 기존 회귀 하네스를 돌린 결과 렌즈는 **이동 판정 14/17**로 살아남았고
(실패 8건은 좌하단 난이도 배지만, 3건은 중국어 화면과 이미 저해상도인 원본),
남은 건 **진짜 캡처가 몇 픽셀을 주는가**다. 헤더 버튼 툴팁의 첫 숫자가 그것이다.

- 실제 프레임이 **960×540 이상** → 이동 판정 통과 기대
- devicePixelRatio가 2인데 프레임이 창 크기와 같다 → 반해상도 확정 (에뮬 창을 키우면 완화)

## 권한

`desktopCapture`(창 선택 피커) 하나뿐. 그 외 없음 —
탭 목록·방문 기록·네트워크 접근 권한을 요구하지 않는다.
캡처한 프레임은 로컬 페이지로만 가고 외부로 나가지 않는다.

## 사이트 쪽

`app/lens/bridge.ts`가 프레임을 받아 `File`로 만들어 각 탭의 `handleLensShot`에 넘긴다 —
클립보드 감시(`lens/clipwatch.ts`)와 **똑같은 자리**다. 그래서 인식·이동 코드는 하나도
새로 쓰지 않았고, 스샷으로 되던 건 브리지로도 그대로 된다.
헤더 버튼은 `app/lens/bridge-button.tsx`.
