# 인프라 역검증 · 엔진 배포 관문

사람들이 저장한 인프라 설정(보유·정예화·편성·고정 — 내 정보로 로그인해 설정 저장소 D1 `prefs` 에 올라온 것)으로
**지금 엔진**을 다시 돌린다. 사용자 결정 2026-10-20: "1주일에 한 번, 검증 끝난 사람은 빼고, 그 뒤에 저장된 설정만으로".
2026-10-21 하루 동안 "됐다" 했다가 배포 뒤에 드러난 실패가 17건 났다(docs/INFRA-FAILURES.md) — 그래서 **엔진을 고치면 배포 전에 관문**을 둔다.

| 신호 | 뜻 | 기준 | 관문 |
|---|---|---|---|
| 회귀 | **기준선**(배포된 엔진들이 그 사람에게 낸 편성 중 지금 채점으로 가장 높은 것)보다 자동편성이 내려갔다 | −0.5점 | ✓ |
| 안정장치 위반 | 그 사람이 지금 자동편성을 누르면 받는 편성(화면과 같은 `keepIfClose`)이 지금 저장 편성보다 낮다 | −0.05점 | ✓ |
| 안정장치 채점 불일치 | 안정장치가 본 지금 편성 점수 ≠ 그 배치를 다시 센 점수 | ±0.05점 | ✓ |
| 다듬기 덜 끝남 | 자동편성 결과를 한 번 더 다듬으면 오른다 — 다듬기가 고정점에 못 닿았다 | +0.5점 | ✓ (시도 상한에 걸린 사람·장기 지속 모드는 따로 — 그 모드는 엔진이 일부러 안 다듬는다) |
| 채점 경로 불일치 | 엔진이 매긴 점수 ≠ 그 배치를 다시 센 점수(손 편집·임시 편성이 쓰는 채점) | ±1점 | ✓ |
| 엔진이 놓친 조합 | 저장 편성(손 편집 포함)이 지금 자동편성보다 높다 — 안정장치가 저장 편성을 지키니 사용자 피해는 없다 | 저장 > 자동 + 5점 | 참고 |
| 지난 판 대비 | 바로 앞 판과 비교 | ±0.5점 | 참고 (판정은 기준선으로) |
| **상식 검사** (`riic-audit-sanity.mjs`, 점수와 무관) | A조가 B조보다 크게 낮음(10%p) · 쓸 수 있는 오퍼가 있는데 빈 칸 · A·B 겹침 · 같은 팀인데 방 % 급변 | 설계상 경우는 따로 표시 | 참고 |

**왜 기준선인가 (2026-10-21):** '지난 판 대비'는 판마다 기준이 옮겨 가서, 한 번 넘어간 회귀가 다음 판에서 사라졌다 — 아침 판 대비
16명(최대 −18.2, 운영자 계정 −0.58 포함)이 내려갔는데 그 뒤 판들이 내려간 판을 기준으로 삼아 "내려감 0"으로 보였다.
**왜 안정장치를 도나:** 종전 작업자는 `optimizeConfig` 까지만 불러서, 사용자가 실제로 겪는 '자동편성을 눌렀더니 내 편성이 더 낮게 바뀜'
(#5·#11·#17)은 907명을 돌려도 0건이었다. **왜 문턱 +0.5인가:** 종전 탐지기 문턱 +5 아래에 운영자 계정 +2.2 가 두 판 연속 묻혔다.
**상식 검사가 왜 따로 있나 (사용자 지적 2026-10-20):** 점수 비교는 엔진 채점 공식을 기준으로 해서 공식이 틀리면 못 잡는다. 제조소 A조 +40%·B조 +95% 처럼
"A조는 주력인데 B조가 높다"는 건 점수와 무관하게 이상하다. 'A<B' 가 남으면 그 방 A·B조를 맞바꿔 총점이 떨어지는지 본다 — 안 떨어지면 엔진 실수(고칠 것),
떨어지면 조 단위로 묶인 편성(그 조 제어센터 오라에 기대는 팀 등)이다.

## 엔진을 고쳤을 때 (배포 전 — 빠뜨리면 ship.sh·deploy.sh 가 멈춘다)

```bash
node scripts/riic-one.mjs            # ① 운영자 계정으로 저장 편성 vs 자동편성 vs 받는 편성 (30~40초) — 고치기 전·후 둘 다 찍어 보인다
node scripts/verify-plan.mjs         # ② 픽스처(정배·절대룰) 회귀 검사
node scripts/riic-audit.mjs --quick  # ③ 관문 — 관문 명단(한 번이라도 문제가 난 계정 + 운영자 계정)만, 기준 입력으로 (5~15분)
#  → 보고서 맨 위 '관문 — ✓ 통과' 여야 푸시·배포된다 (.git/riic-gate.json 에 엔진 해시와 함께 남는다 — 엔진을 한 글자라도 고치면 다시)
#  → 걸리면 그 목록부터 원인을 본다. 내려간 게 맞다고 판단한 계정(고정을 새로 지키게 됨 등)은 **사용자 확인 뒤**
#     node scripts/riic-audit.mjs --accept 계정,계정  (그 계정 기준선을 새 결과로) → --quick 다시
node scripts/riic-audit.mjs --rerun  # ④ 엔진을 크게 고쳤으면 전원(907명, 1~1.5시간)도 — 관문으로 쓸 수 있다
```

- **원인을 재현 없이 적지 않는다.** 증상을 riic-one(또는 한 계정 진단)으로 숫자부터 재현하고, 고친 뒤 같은 도구로 사라졌는지 본다
  (2026-10-21 #17: 원인 설명이 두 개였는데 하나는 그 계정에 해당이 없었고, '안정장치가 비교를 안 했다'는 재현되지 않았다).
- **무거운 계산은 하나씩** — riic-audit·riic-explain 은 같은 잠금(`.riic-audit/.busy.json`)을 잡는다. 겹치면 뒤에 띄운 쪽이 멈춘다.
- 배포가 끝나면 deploy.sh 가 `--deployed` 로 배포한 엔진 해시를 적고, 그 엔진의 관문 판을 기준선에 올린다(계정마다 기준선과 높은 쪽).

## 주간 점검

```bash
node scripts/riic-audit.mjs          # 검증완료가 아닌 계정만 D1 에서 새로 받아서 (처음이거나 검증 뒤 설정이 바뀐 계정) — 10~15분
#  → 보고서 .riic-audit/runs/<시각>/report.md 를 읽고 유형별로 원인을 찾는다 (아래 '진단')
#  → 엔진을 고치면 위 '엔진을 고쳤을 때' 순서
# 돌리는 동안 감시: 이상이 하나라도 나오면 **끝까지 기다리지 말고 그 자리에서 멈추고 고친 뒤 다시** (사용자 지시 2026-10-20).
node scripts/riic-audit.mjs --mark   # 마지막에 — **기록만**: 마지막으로 끝난 판에서 문제 없던 계정을 검증완료로 (아무것도 안 돌린다)
node scripts/riic-explain.mjs        # 오퍼별 효과 전수 조사 (아래) — 역검증이 끝난 뒤에
```

- **검증완료 플래그** = `.riic-audit/verified.json` 의 `{계정: 그때 설정의 t}`. 설정 저장소의 `t` 는 그 사람이 설정을 바꿀 때마다 오른다 —
  자동편성을 다시 돌려도 편성이 저장되므로 오른다. 사용자 계정에 플래그 키를 쓰지 않는다(그 사람 브라우저로 동기화되고 D1 쓰기가 는다).
  (2026-10-21 #16: 종전 `--mark` 는 D1 에서 받아 전원을 다시 돌리는 실행 옵션이었다 — 1시간 반을 돌다 멈췄다)
- `--all` 은 D1 에서 전원 새로. `--rerun` 은 받기 없이 기준 입력(기준선을 만든 판의 입력) 전원.
- **기준선** = `.riic-audit/baseline.jsonl`(계정마다 편성) + `baseline.json`(기준 입력·올린 판 이력). 설정(t)이 기준선 때와 같은 계정만 회귀를 본다.
  `--promote <판>` 으로 올린다(기본은 계정마다 높은 쪽, `--replace` 는 덮기). 처음 만든 것(2026-10-21): 아침 판(00-29)과 저녁 판(08-30) 중 높은 쪽.
- **관문 명단** = `.riic-audit/watch.json` — 판마다 문제 난 계정이 저절로 더해진다(`--rewatch <판>` 으로 옛 판에서도). `--quick` 이 이 명단 + 운영자 계정(`.riic-audit/owner.txt`)을 돈다.
- **데이터는 남의 계정이다** — `.riic-audit/` 는 gitignore. 보고서 내용(계정 코드)을 커밋·업데이트 내역·답변에 싣지 않는다.
- D1 은 `workers/account` 에서 `npx wrangler d1 execute terra-archive-prefs --remote` 로 읽는다. 한 번 7403(권한) 오류가 나도 일시적일 수 있다 —
  `npx wrangler whoami` 로 계정(nzkonaru)·d1 권한을 보고 다시 시도 (2026-10-20 처음엔 실패, 바로 다시 하니 됐다).

## 오퍼별 효과 전수 조사 (주 1회 — 역검증과 같이, 사용자 지시 2026-10-21)

```bash
node scripts/riic-explain.mjs            # 무작위 100명 자동편성 → 모든 오퍼 자리의 효과를 엔진 값 vs 스킬 문구로 따로 센 값으로 대조 (작업자 7, 10~15분)
#  → .riic-audit/explain/<시각>/report.md (어긋난 오퍼·예시·따로 셀 방법이 없는 스킬 순위) · ops.jsonl (자리마다 풀이)
node scripts/riic-explain.mjs --n 300    # 시간 여유가 있으면 더 많이
```

- **목적:** 엔진이 '세는 법' 자체를 틀린 곳을 잡는다 — 점수 비교(역검증)는 엔진 공식을 기준으로 해서 공식이 틀리면 못 잡는다.
  예: 내스티 '기반시설 내 라인 랩 1명당'을 숙소 빼고 세던 것(제보 8a92310b).
- **어긋남이 나오면** 그 오퍼 스킬 문구와 배치표를 보고 둘 중 누가 틀렸는지 가린다. 엔진이 틀렸으면 고치고 역검증, 계산기가 틀렸으면 계산기(`independent()`)를 고친다.
- **'따로 셀 방법이 없는 스킬'** 순위 위에서부터 `independent()` 에 문구 종류를 하나씩 더한다(첫 판 2026-10-21: 따로 센 비율 63%).
  자동화·덮어쓰기·토큰·짝 조건은 방 전체 규칙이라 지금은 '못 셈'으로 둔다.
- 입력은 역검증 기준 입력(전원)에서 뽑는다 — 관문 판(--quick)은 문제 났던 계정만이라 치우친다.
- 토큰은 안 든다 — 돌리는 동안은 로컬 노드, 사람이 보는 건 보고서의 어긋남 목록뿐.

## 진단 요령

- **같은 채점으로 비교한다.** 저장 편성·자동편성·기준선·지난 판 모두 배치에서 다시 센 점수(`rescorePlan` — 손 편집·안정장치·다듬기와 같은 채점,
  riic-lib.mjs `rescore`)로 매긴다. 엔진 자체 점수(`auto`)와 섞으면 '놓침'이 두 배로 부풀었다(107명 → 실제 42명).
- 시험 도구에서 저장 편성의 다른 값(`plants`·`shiftHours` 등)을 섞어 쓰지 말 것 — 비교가 어긋난다.
- 한 사람 재현: `node scripts/riic-one.mjs <계정>` — 기준 입력(없으면 마지막 판 입력)에서 그 계정을 꺼내 작업자와 같은 순서로 기지를 세우고
  자동편성·한 번 더 다듬기·안정장치까지 찍는다. `--fresh` 는 D1 에서 그 계정만 새로 받는다.
- 고친 것(2026-10-20): ① 방 고정을 조 구분 없이 칸 수만큼만 받아 B조 고정이 A조 고정을 밀어내던 것 ② 감사가 사람을 바꾼 뒤 진영 인원 수를 안
  갱신하던 것(엔진·화면 채점이 ±90점 어긋남) ③ 화면·안정장치가 진영 수를 따로 세던 것(`factionCountsFor` 로 통일).
- 고친 것(2026-10-21): 다듬기를 고정점까지(교체 ↔ 정리 반복) · 다듬기 시간 상한 없앰(결과가 기기 부하에 따라 바뀌었다) · 고정 비중 판도
  지금 채점으로 다듬기 · 안정장치는 쓸 수 없는 편성일 때만 비교 없이(사유를 남긴다) · 더 낮은 편성으로 바꿀지 묻지 않기.
- 마무리 교체(`polishPlan`)는 2026-10-20 부터 자동편성 끝에 붙어 있다(장기 지속 모드 제외). 확정 정배(제어센터 링·시·총웨 등)도 점수가 지면 바뀐다.
- 확정 규칙(INFRA-RULES·rules.json fixtures)을 뒤집는 결과가 나오면 **고치지 말고 수치와 함께 사용자에게 묻는다.**
