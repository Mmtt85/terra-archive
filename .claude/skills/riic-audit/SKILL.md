# 인프라 역검증 (주 1회)

사람들이 저장한 인프라 설정(보유·정예화·편성·고정 — 내 정보로 로그인해 설정 저장소 D1 `prefs` 에 올라온 것)으로
**지금 엔진**을 다시 돌려 세 가지를 찾는다. 사용자 결정 2026-10-20: "1주일에 한 번, 검증 끝난 사람은 빼고, 그 뒤에 저장된 설정만으로".

| 신호 | 뜻 | 기준 |
|---|---|---|
| 엔진이 놓친 조합 | 그 사람이 저장한 편성(손 편집 포함)이 지금 자동편성보다 높다 | 저장 > 자동 + 5점 (같은 채점으로) |
| 채점 경로 불일치 | 엔진이 매긴 점수 ≠ 그 배치를 다시 센 점수(손 편집·임시 편성이 쓰는 채점) | ±1점 |
| 회귀 | 지난 판보다 자동편성 점수가 내려갔다 | −0.5점 |
| 탐지기 | 마무리 교체(`polishPlan`)가 같은 채점으로 더 올린다 — 엔진이 방을 넘는 효과를 놓친 곳 | +5점 |
| **상식 검사** (`riic-audit-sanity.mjs`, 점수와 무관) | A조가 B조보다 크게 낮음(10%p) · 쓸 수 있는 오퍼가 있는데 빈 칸 · A·B 겹침 · 같은 팀인데 방 % 급변 | 설계상 경우(장기 지속 모드·B조 결집 세트·토큰 생성원)는 따로 표시 |

**상식 검사가 왜 따로 있나 (사용자 지적 2026-10-20):** 점수 비교는 엔진 채점 공식을 기준으로 해서 공식이 틀리면 못 잡는다. 제조소 A조 +40%·B조 +95% 처럼
"A조는 주력인데 B조가 높다"는 건 점수와 무관하게 이상하다 — 이 검사가 있었으면 제어센터 오라 이중 계산을 바로 잡았다. 'A<B' 가 남으면
그 방 A·B조를 맞바꿔 총점이 떨어지는지 본다 — 안 떨어지면 엔진 실수(고칠 것), 떨어지면 조 단위로 묶인 편성(그 조 제어센터 오라에 기대는 팀 등)이다.

## 순서

```bash
node scripts/riic-audit.mjs          # 검증완료가 아닌 계정만 (처음이거나 검증 뒤 설정이 바뀐 계정) — 10~15분
#  → 보고서 .riic-audit/runs/<시각>/report.md 를 읽고 유형별로 원인을 찾는다 (아래 '진단')
#  → 엔진을 고치면: node scripts/verify-plan.mjs (회귀 검사) → node scripts/riic-audit.mjs --rerun (같은 사람들로 '역의 역검증')
#     → 놓친 수가 줄고 **회귀(내려감)가 0** 이어야 끝. 내려간 사람은 하나씩 원인을 본다(고정을 새로 지키게 된 경우처럼 정상일 수 있다)
# 돌리는 동안 감시: 이상이 하나라도 나오면 **끝까지 기다리지 말고 그 자리에서 멈추고 고친 뒤 다시** (사용자 지시 2026-10-20).
#   감시 스크립트는 1분마다 끝난 사람들을 보고(회귀·채점 불일치·A·B 겹침·'맞바꿔도 손해 아닌 A<B') 이상이면 종료해 세션을 깨운다.
#   돌리는 동안은 토큰이 거의 안 든다(계산은 로컬 노드). /loop 는 필요 없다 — 감시 스크립트가 끝날 때 알림이 온다.
node scripts/riic-audit.mjs --mark   # 마지막에 — 문제 없던 계정을 검증완료로 기록 (문제 있던 계정은 다음 주에 다시 본다)
```

- **검증완료 플래그** = `.riic-audit/verified.json` 의 `{계정: 그때 설정의 t}`. 설정 저장소의 `t` 는 그 사람이 설정을 바꿀 때마다 오른다 —
  자동편성을 다시 돌려도 편성이 저장되므로 오른다(사용자 제안 "자동편성을 돌리면 플래그를 false 로"와 같은 효과). 사용자 계정에 플래그 키를
  쓰지 않는다(그 사람 브라우저로 동기화되고 D1 쓰기가 는다).
- `--all` 은 엔진을 크게 고친 뒤 전원 다시. `--rerun` 은 받기 없이 지난 판의 같은 입력으로.
- **데이터는 남의 계정이다** — `.riic-audit/` 는 gitignore. 보고서 내용(계정 코드)을 커밋·업데이트 내역·답변에 싣지 않는다.
- D1 은 `workers/account` 에서 `npx wrangler d1 execute terra-archive-prefs --remote` 로 읽는다. 한 번 7403(권한) 오류가 나도 일시적일 수 있다 —
  `npx wrangler whoami` 로 계정(nzkonaru)·d1 권한을 보고 다시 시도 (2026-10-20 처음엔 실패, 바로 다시 하니 됐다).

## 오퍼별 효과 전수 조사 (주 1회 — 역검증과 같이, 사용자 지시 2026-10-21)

```bash
node scripts/riic-explain.mjs            # 무작위 100명 자동편성 → 모든 오퍼 자리의 효과를 엔진 값 vs 스킬 문구로 따로 센 값으로 대조 (작업자 7, 10~15분)
#  → .riic-audit/explain/<시각>/report.md (어긋난 오퍼·예시·따로 셀 방법이 없는 스킬 순위) · ops.jsonl (자리마다 풀이)
node scripts/riic-explain.mjs --n 300    # 시간 여유가 있으면 더 많이
```

- **목적:** 엔진이 '세는 법' 자체를 틀린 곳을 잡는다 — 점수 비교(역검증)는 엔진 공식을 기준으로 해서 공식이 틀리면 못 잡는다.
  예: 내스티 '기반시설 내 라인 랩 1명당'을 숙소 빼고 세던 것(제보 8a92310b).
- **어긋남이 나오면** 그 오퍼 스킬 문구와 배치표를 보고 둘 중 누가 틀렸는지 가린다. 엔진이 틀렸으면 고치고 역검증, 계산기가 틀렸으면 계산기(`independent()`)를 고친다.
- **'따로 셀 방법이 없는 스킬'** 순위 위에서부터 `independent()` 에 문구 종류를 하나씩 더한다(첫 판 2026-10-21: 따로 센 비율 63%).
  자동화·덮어쓰기·토큰·짝 조건은 방 전체 규칙이라 지금은 '못 셈'으로 둔다.
- 토큰은 안 든다 — 돌리는 동안은 로컬 노드, 사람이 보는 건 보고서의 어긋남 목록뿐.

## 진단 요령 (2026-10-20 첫 판에서 배운 것)

- **같은 채점으로 비교한다.** 저장 편성은 배치에서 다시 센 원장으로 매기므로 자동편성도 `autoRe`(다시 센 점수)로 비교한다.
  엔진 자체 점수(`auto`)와 섞으면 '놓침'이 두 배로 부풀었다(107명 → 실제 42명).
- 시험 도구에서 저장 편성의 다른 값(`plants`·`shiftHours` 등)을 섞어 쓰지 말 것 — 비교가 어긋난다. 작업자의 `rescore` 를 쓴다.
- 한 사람 재현: `.riic-audit/runs/<시각>/input.json` 에서 그 계정 행을 꺼내 작업자와 같은 순서(재활용소→배치→레벨→훈련실)로 기지를 세우고
  `optimizeConfig` → 방별로 저장 편성과 비교한다.
- 고친 것(2026-10-20): ① 방 고정을 조 구분 없이 칸 수만큼만 받아 B조 고정이 A조 고정을 밀어내던 것 ② 감사가 사람을 바꾼 뒤 진영 인원 수를 안
  갱신하던 것(엔진·화면 채점이 ±90점 어긋남) ③ 화면·안정장치가 숙소까지 진영 수에 넣던 것(`factionCountsFor` 로 통일).
- **탐지기(`polishPlan`)는 자동편성에 붙이지 않았다** — 보유 전원 로스터에서 +224점을 내며 확정 정배(제어센터 링·시·총웨)를 허물었다.
  채점이 쉐이 패키지를 낮게 보는지, 정배가 낡았는지 사용자와 가린 뒤에만 붙인다. 그 전까지는 '어느 방에서 놓치나'를 알려 주는 용도.
- 확정 규칙(INFRA-RULES·rules.json fixtures)을 뒤집는 결과가 나오면 **고치지 말고 수치와 함께 사용자에게 묻는다.**
