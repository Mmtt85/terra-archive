# 한국서버 작은 점검 대응 — 열린 게 제대로 뜨는지만 본다

## 이 점검의 성격 (사용자 확정 2026-08-13)

오후 4시부터 **10분 남짓**. 큰 점검(오전 10시~오후 4시) 때 클라에 이미 들어온 데이터를
**스위치만 켜서 하나씩 해금**한다. 그래서:

- **새 데이터를 받을 게 대개 없다.** 파이프라인 풀런은 과잉이다 — 큰 점검 쪽 스킬([`kr-big-patch`](../kr-big-patch/SKILL.md))을 부르지 말 것.
- 할 일은 **"열린 게 사이트에 제대로 뜨는가"** 확인이다. 과거 실제 작업도 전부 그쪽이었다:
  - 2026-07-30 16:48 이벤트 배너 — 섬네일 없는 게임 모드를 종류 기호로
  - 2026-07-31 16:08 공지 매칭 — 문장부호 차이로 **메인 이벤트가 링크 안 되고 곁다리 출석 이벤트만** 붙던 문제
  - 2026-07-31 16:13 부 이벤트 숨김 — 출석·로그인 계열 7종 추가

## 절차

### 1. 정말 데이터가 안 바뀌었는지만 확인 (30초)
```bash
python3 scripts/whatsnew-gamedata.py --future-only
```
신규 이벤트 행이 뜨면 그건 작은 점검이 아니라 **추가 배포**다 → `kr-big-patch`로 넘어간다.

### 2. 방송 워커가 새 이벤트를 물었는지 — **여기가 제일 흔한 원인**
```bash
curl -s https://terra-archive-broadcast.nzkonaru.workers.dev/ | python3 -m json.tool | head -40
```
크론이 **6시간 주기**(`23 */6 * * *`)라 16시에 열린 이벤트가 최대 6시간 뒤에야 뜬다.
`events`에 없으면 KV를 비워 즉석 재수집시킨다:
```bash
npx wrangler kv key delete broadcasts --namespace-id=b6445de857bc40fc83595aa8132ccd75 --remote
curl -s https://terra-archive-broadcast.nzkonaru.workers.dev/ >/dev/null   # 재수집 트리거
```

### 3. 화면 확인 (3언어)
로컬 프로덕션(`npm run start`)이나 라이브에서 헤더 **진행중 이벤트** 배지·드롭다운을 본다.
- 새 이벤트가 **대표 배지**로 잡히는가 (사이드스토리·복각이 로그인·출석류보다 우선)
- **공지 링크**가 메인 이벤트에 붙었는가 — `app/home.tsx`가 아니라 워커의 `noticeUrlFor()`가
  붙인다. 게임명과 공지 제목의 문장부호가 다르면 안 붙는다(`normTitle`이 한글·영숫자만 남겨
  비교하도록 고쳐 뒀다). 곁다리 출석 이벤트에만 링크가 붙었으면 그 회귀다.
- **부 이벤트가 숨겨지는가** — 출석·로그인·기원류는 헤더에서 아예 뺀다(사용자 확정 2026-07-17).
  새 `type`이 등장했으면 `app/home.tsx`의 숨김 목록(L366 부근)에 추가한다.
  ⚠ 짐작하지 말고 `activity_table`을 전수로 훑어 그 type의 실제 이벤트명을 주석에 남길 것.
- 시작 전 이벤트는 **오늘 시작 / 시작 D-N**이 맞는지 (KST 달력 날짜 차이로 센다 — 시분 차를
  올림하면 오늘 16시 시작이 'D-1'로 나온다, 2026-08-13 수정)

### 4. `MANUAL_EVENTS` 정리
`workers/broadcast/src/index.js`의 손수 넣은 항목 중, 실데이터가 들어온 것은 지운다.
(id가 겹치면 자동으로 버려지고 `until`이 지나면 무시되므로 급하진 않지만, 남겨두면
다음 사람이 "왜 두 군데에 있지" 하게 된다.)

### 5. 해금된 게 **콘텐츠**면 그때만 파이프라인
새 스테이지·구역·통합전략 확장팩이 열렸으면 그 부분만:
```bash
python3 scripts/build-enemies.py && python3 scripts/build-stages.py   # 신규 도면·등장 적
node scripts/r2-sync.mjs                                              # 이미지가 R2로 가야 보인다
```
통합전략이면 `rm -f .gamedata/rogue/*roguelike_topic_table.json` 후 `build-rogue.py`
(캐시가 영구 보존이라 지우지 않으면 옛 표를 계속 쓴다 — `kr-big-patch` §3 참조).

### 6. 마무리
코드를 고쳤으면 `npm run build` → 커밋 → push. **`scripts/deploy.sh`는 실행 금지.**
워커만 고쳤으면 `bash workers/broadcast/deploy.sh` (사이트 배포 금지 규칙과 별개지만
사용자에게 한 줄 보고할 것).

## 아무 문제 없으면

"열린 것: <이벤트명> / 배너·공지 링크·숨김 규칙 정상 / 손댈 것 없음"으로 짧게 끝낸다.
확인이 본체인 스킬이므로 **없는 일을 만들지 말 것.**
