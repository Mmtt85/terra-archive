# 적 이동 경로 지도 — 확정 규칙 (2026-08-10 사용자 확정)

작전 상세의 '이동 경로' 탭. 레벨 파일의 타일 격자를 SVG로 그리고 그 위에 적 경로
폴리라인을 겹친다. 아래 규칙들은 전부 사용자가 실화면을 보며 확정한 것 —
**임의로 바꾸지 말고, 바꾸라는 지시가 오면 이 문서와 코드 주석을 함께 갱신**한다.

## 적용 지점 (동일 규칙·동일 컴포넌트)

| 화면 | 데이터 | 배선 |
|---|---|---|
| 작전 도감 상세 (`app/stage-detail.tsx`) | `stage-routes.json` · 통합전략 `rogue-routes.json` · 생존연산 `sandbox-routes.json` | 합친 도면이면 상세를 열 때, 아니면 탭 클릭 시 지연 로드 (모듈 캐시) |
| 통합전략 전투 노드 모달 (`app/rogue.tsx`) | `app/data/rogue-routes.json` | 〃 (긴급 노드는 일반 노드 별칭 문자열) · 카메라 `rogue-cams.json` |
| 생존연산 지역 상세 모달 (`app/sandbox.tsx`) | `app/data/sandbox-routes.json` | 〃 (build-sandbox.py — routeutil 공유, 시뮬 확장 포함) · 평면도 `sandbox-ortho.json` |

렌더러는 `app/stage-route-map.tsx`의 `StageRouteMap` 하나 — 새 화면에 붙일 때도
이 컴포넌트를 재사용하고 복제하지 않는다.

## 데이터 파이프라인

- 추출 정본: `scripts/routeutil.py`의 `routes_of_level(lv)` — 레벨 JSON →
  `{h, w, g(행 문자열), r(경로 꼭짓점), f(비행 플래그), e(적 id → 경로 번호)}`.
  `scripts/build-enemies.py`(stage-routes.json)와 `scripts/build-rogue-routes.py`
  (rogue-routes.json)가 공유한다 — **로직을 한쪽에만 고치면 안 된다** (공유 모듈이므로
  고칠 곳은 routeutil.py 한 곳).
- 경로 = startPosition + MOVE 체크포인트 + endPosition. **routes 배열의 자리를
  지우면 안 된다** — waves가 routeIndex 번호로 가리킨다. 못 그리는 경로는 null.
- 적↔경로 연결: waves/branches의 SPAWN 액션 (`key`, `routeIndex`).
  ⚠ **그 번호가 가리키는 배열이 둘로 갈린다** — waves 는 `routes`, **branches(기믹 소환)는
  `extraRoutes`** 다. 2026-09-13 제보로 발견: IS-EX 의 '패밀리 어둠의 멸살자'가 빨간 출현칸이
  아니라 엉뚱한 이동 타일에서 시작했다. 같은 0번이라도 웨이브는 `routes[0]`, 브랜치는
  `extraRoutes[0]` 이라 **남의 경로를 덮어 그리고 있었다**(365개 레벨·693조합).
  `routes_of_level` 은 두 배열을 이어 붙이고(기존 번호 보존) 브랜치에만 오프셋을 더한다.
  전수 검증에서 웨이브 65,861건이 100% `routes` 범위 안, 브랜치 2,367건이 100% `extraRoutes`
  범위 안이라 배열로 가르는 것이 안전하다. `managedByScheduler` 는 양쪽 다 true 라 판별에 못 쓴다.
  `motionMode` 가 `E_NUM` 인 extraRoutes 는 빈 자리이므로 경로 없음으로 떨어뜨린다
  (위수 협의 연습 맵의 소환 더미 — 예전엔 이 자리에 남의 경로가 그려졌다).

## ⚠ 좌표계 함정 (한 번 틀렸던 것)

- 타일 행렬 `g`: **row 0 = 위** (render_minimap 규약, 실사 도면과 육안 대조로 확정).
- 경로 좌표 `r`: **row 0 = 아래** (게임 월드 원점이 좌하단).
- → 렌더러가 경로만 상하 반전한다 (`h - 1 - row`). 새 데이터 소스를 붙일 때 이 반전을
  빼먹으면 "뭔가 뒤집힌 것 같은데"가 재현된다.

## 타일 분류 (`routeutil.py` tchar)

tileKey 이름 추측이 아니라 **속성**(passableMask·buildableType·heightType)으로 분류한다.
문자: `s`출현 `e`방어 `r`도로 `p`이동만 `b`배치만(펜스) `w`고지대(원거리) `x`고지형불가
`f`장애물 `h`구멍(비행만) `i`통로입구 `o`통로출구. 예외 tileKey 직접 매핑: start/flystart→s,
end→e, hole→h, telin→i, telout→o. 범례 라벨은 라벨 자체가 설명이 되게 쓰고("이동
가능·배치 불가"), 색은 회색 일색이 안 되게 색조를 섞는다. 툴팁(data-tip)은 지연 없이 즉시.
`u`물(지상·비행 통과 — 생존연산은 수상 플랫폼을 놓아야 배치 가능) `d`깊은 물(비행만).
`x`(고지형 이동·배치 불가)는 **배경을 아주 새까만색(#0b0a12)**으로 하고 그 위에
**타일 중앙의 은은한 ⊘(원+사선) 금지 표식**(밝은 잉크 #4f4964)을 겹친다 (사용자 확정
2026-08-10 — 단순 세로 줄무늬 안은 무성의하다고 반려, "배경색을 새까만색으로" 재지시.
⊘를 검게 칠하는 게 아니다). SVG defs `<g>` 하나를 `<use>`로 재사용, 범례 스와치도
같은 ⊘. 더 요란하게 키우지 말 것.

## 지상 경로 = BFS 보행 (직선 금지)

- 이동 가능 타일 `WALKABLE = {r, p, s, e, i, o, u}` 위에서 8방향 BFS.
  ⚠ 물(u)은 passableMask=ALL이라 **지상 적도 걸어서 건넌다** — 비행 전용이 아니다
  (2026-08-12 사용자 지적으로 WALKABLE에 추가). 비행만 지나는 건 깊은 물(d)·구멍(h)뿐.
  대각선은 **모서리 뚫기 금지** (양옆이 다 통행 가능할 때만).
- **통로 입구(i)에서 모든 출구(o)로 순간이동 간선** — 11-2처럼 통로 너머로 이어지는
  경로가 고지형을 뚫는 직선으로 그려지던 문제의 해법.
- BFS 실패(특수 좌표) 시 직선 폴백. 비행(f=1)은 실제로 지형을 무시하므로 직선 그대로.
- 비인접 연속 칸(순간이동 hop)은 구간을 끊고 가늘고 성긴 점선으로만 잇는다.

## 선 그리기 모델 — 사용자 7차 확정 (가장 많이 틀렸던 곳)

> **선은 적 단위로 그린다.**
> ① 같은 적 + 같은 경로 = 같은 색 **한 줄**
> ② 같은 적 + 다른 경로 = 같은 색 **다른 줄** (약간 어긋나게)
> ③ **서로 다른 적은 경로가 같아도 항상 별도 줄** — 각자 자기 색으로 나란히
>   (0-2에서 원석충·병사가 같은 복도를 걸으면 노랑·초록 두 줄).
> ③을 어기고 기하만으로 전역 병합했다가 7번째 지적을 받았다 (2026-08-10) — 다시
> "경로가 같으니 한 줄" 쪽으로 최적화하지 말 것.

- "같은 경로(기하)" 판정: ① 원본 경유점열이 완전히 같다, 또는 ② 출발·도착·비행
  모드가 같고 **밟는 타일(dense)의 대칭차가 2칸 이하**. 게임이 스폰마다 한 칸씩
  엇갈려 짜는 지터 복제는 차이 1~2칸이라 접히고, 진짜 다른 길(11-19 윗길 vs 오른길)은
  4칸 이상이라 남는다 — 11-19 실데이터로 역산해 확정한 문턱값. 추이적 병합(변화가
  없을 때까지 반복), 대표는 경유점이 가장 많은 변형.
- 이 기하 접기는 **한 적 안에서** 지터 복제·중복 인덱스를 한 줄로 만드는 용도다
  (11-12: 왕정군 전사 단독 등록 + 전사·부패의 전사 공용 등록이 같은 길 → 전사는 한 줄).
  서로 다른 적끼리 합치는 데 쓰면 안 된다.
- 등장 적 목록 밖(숨은 증원 등)만 쓰는 경로는 회색 한 벌로 남긴다.
  ⚠ 단 **어느 SPAWN 도 안 쓰는 경로는 그리지 않는다** (사용자 제보 2026-09-23 TR-5 "정체를 알 수
  없는 회색 경로"). 레벨 routes 에는 PREVIEW_CURSOR(웨이브 예고 화살표 998개)·PLAY_OPERA(경고
  연출 143개)·DISPLAY_ENEMY_INFO 가 가리키는 경로가 섞여 있어, 작전 도감 401곳에 1,163개가
  회색으로 나가고 있었다. 판정은 `e`(웨이브·브랜치 SPAWN 전부, 숨은 증원 포함)에 한 번도 안
  나오는 경로 = 적의 길이 아니다.
- 검증 기준 스테이지: 0-2 = 원석충·병사 각자 색 별도 줄, 11-19 전사 = 노란 2줄
  (윗길/오른길), 11-12 전사 = 1줄, 11-2 = 통로 경유.

## 색·강조·스타일

- 적별 색: `ROUTE_COLORS` 8색을 **범례(등장 적) 순번**으로 배정 — 같은 적은 같은 색,
  다른 적은 다른 색. 카드 테두리(--rc)와 지도 선이 같은 색을 공유한다.
  선이 적 단위이므로 선 색은 언제나 그 선 주인의 색이다 (공유 경로 색 갈림 없음).
- 강조: 고른 적의 선 굵게(0.12), 나머지는 **아주 흐리게**(그룹 opacity 0.07) — '굵기만'
  안을 써 보고 겹침이 심해 흐림으로 되돌린 것이므로 다시 왕복하지 말 것.
- 겹침 오프셋: 선 단위 대각 오프셋, 간격 0.07타일 지향하되 **타일 폭(±0.2)은 절대
  안 벗어난다** — 경로가 많으면 간격을 줄여서라도 안에 담는다.
- 대시: 지상 "0.5 0.14" · 비행 "0.12 0.2" · hop "0.04 0.12"(가늘게·opacity 0.55).
  진행 방향으로 흐르는 애니메이션(stroke-dashoffset -0.64 = 패턴 길이 공배수,
  prefers-reduced-motion이면 정지). 시작점 ●(r 0.16) + 도착점 화살촉(0.28).

## 상호작용 (작전 도감·통합전략 공통)

- 등장 적 **카드 클릭 = 경로 고정 토글** (여러 적 중첩, 색 테두리 + ✓ 배지).
- **지도 위 선 클릭도 같은 고정 토글** (onPick, 투명 히트 선에 cursor:pointer —
  사용자 요청 2026-08-10). 주인 없는 회색 선(목록 밖 증원)은 클릭 무동작.
- 카드 **호버 = 그 적만 잠깐 강조** + 경로 있는 카드는 색 보더 미리보기.
- 선·말 **호버 = 이름 + 작은 섬네일** 즉시 툴팁 (.st-maptip — 사용자 요청 2026-08-10
  "섬네일 이미지도 작게 같이").
- **경로 주인의 이름·초상은 화면 이름표 밖이면 경로 문서의 `nm`**(scripts/routenames.py)으로 채운다 — 그 판 전용
  변종(enemyDbRefs `useDb:false`, 이름·모델을 레벨 파일에 직접 적는다)·도감 밖 적이 이름표에 없어 id 가 찍히고
  말이 까맣게 비던 것 (사용자 제보 2026-09-23 흑류수해 시뮬레이터, 전수 248종). 한국어 화면은 그 판 이름
  ('사냥개 (약)'), 중섭 선행은 원문 + 모델 적 번역, 영·일은 모델 적의 현지 이름. 초상은 모델 적 것이고,
  게임에도 초상이 없는 적(장치·소환물 25종)·불러오다 깨진 그림은 **말을 경로 색으로 채운다**(검은 원 금지).
  고르는 규칙은 StageRouteMap `ownerName`·`ownerImg` 한 곳 — 화면마다 따로 만들지 않는다.
- 카드 속 **섬네일 클릭 = 항상 적 상세 모달** (stopPropagation으로 고정과 분리).
- 지상/비행 선 범례는 지도 **바깥** 오른쪽 위, 타일 범례는 지도 아래에 **그 지도에
  있는 종류만**. ⚠ 지도 오브젝트(생존연산 파괴 가능 바위)는 **타일이 아니므로 타일
  범례에 섞지 않는다** — 지역 모달의 '자원·오브젝트' 목록이 맡는다 (사용자 지적 2026-08-12).
- 범례 줄 오른쪽의 **⤢ 지도 확대 = 모달 절반 폭까지** (사용자 요청 2026-08-12).
  .st-routewrap.big을 모달 칼럼 그리드가 `:has()`로 받아 360px → 52%로 넓힌다
  (작전 도감 .st-cols · 통전 .rg-modal-cols 공통 — 새 모달에 붙이면 그 칼럼도 등록).
  ⚠ 이 넓히기 규칙은 **넓은 화면용 @media(min-width) 안에** 둔다. `:has(.big)`은 특이도가 폰 1단 규칙보다
  높고 경로 지도는 .big을 늘 달고 나와서, 밖에 두면 폰에서도 2단이 되어 적 칸이 옆으로 넘친다
  (2026-09-23 390px 실측 — 작전 도감·통전·위수 협의 전부. 경계는 각 칼럼의 1단 접힘 폭과 짝).

## 시뮬레이션 — '시뮬레이트' 버튼 (2026-08-10)

- 데이터: `routeutil.py` 시뮬 확장 `sp`/`wv`/`ems`/`cw`/`mm` — 필드 정의는 그 docstring이
  정본. 적 id는 **e 키 순서 번호**로 압축한다 (문자열 반복만 1MB, 실측 후 인덱스화).
  같은 레벨을 공유하는 작전은 별칭 문자열 (stage·rogue 공통 규약).
- 기준선: **저지 없이 흘려보냈을 때** — 웨이브는 마지막 적이 도착 지점에 닿으면 끝나고
  postDelay + 다음 preDelay 뒤에 이어진다 (maxTimeWaitingForNextWave ≥ 0이면 그로 상한).
  branches(처치 수 등 조건 분기 증원)는 시각이 데이터로 확정되지 않아 **재생 제외 + 고지**.
- 경유 대기(cw)는 이동 시간에 뭉개지 않는다 — 점이 제자리에 서도록 도착(arr)/출발(dep)
  시각표를 분리. 조각/웨이브 시계 대기(모드 1/2)는 절대 시각으로 환산해 늦으면 대기 0.
- 통로 순간이동(hop)은 0초 즉시. 이속은 enemyDbRefs 레벨·오버라이드 반영(ems)에
  레벨 전역 배율(mm)을 곱한다.
- 배율 수치가 없는 강화(보안 파견 위험 등급 등)는 시뮬 스탯에 지어 넣지 않는다.
- 말은 **화면에 그려진 그 선**(묶음 대표 best + 오프셋)을 탄다 — 자기 변형 경로를 타면
  지터만큼 선을 벗어난다 (사용자 지적 2026-08-10). 말 = 적 섬네일 + 진행 방향 화살촉
  (원만으론 정지 시 방향을 모른다 — 사용자 지적). 강조 중엔 선과 똑같이 흐려진다.
- **한 칸짜리 경로(제자리 개체)** — 생존연산 채집물·장치처럼 시작=끝인 스폰은 k-1이
  음수가 되어 터졌다 (2026-08-12 그물망 갱도 사용자 제보). 제자리 말로 그리고(화살촉
  없음) 끝 시각을 스테이지 끝으로 늘려 한 프레임만 반짝하지 않게 한다.
- 선·말 호버 = 적 이름+섬네일 즉시 툴팁(.st-maptip, 커서 추적). 본선이 얇아 폭 0.3 투명
  히트 선을 겹친다 — 이 히트 선이 클릭 고정(onPick)도 받는다.

## 작전 시뮬레이터 런처 (/sim — 2026-08-10 B안)

- **작전 리스트를 복제하지 않는다** (사용자 확정): `/sim`은 검색창 + 추천 몇 개짜리 얇은
  런처(`app/sim-launcher.tsx`)고, 정본은 언제나 작전 상세의 '이동 경로' 탭이다.
- **카드 클릭 = 상세 모달** (작전 도감과 같은 창·해시 `#st-<id>`) — 페이지가 넘어가면
  안 된다 (사용자 지시 2026-08-10). href(`/stages/<id>?sim=1`)는 크롤러·새 탭·보조클릭용.
- 검색은 **버튼(또는 Enter)으로 확정** — 입력 즉시 결과 그리드를 갈아끼우지 않는다
  (사용자 지시 2026-08-10). 드롭다운 제안(SearchSuggest)만 입력을 따라 라이브
  (같은 날 "다른 검색란처럼 드롭다운" 지시 — 한 작전 바로 점프 용도). IME 조합 중
  Enter는 검색으로 치지 않는다.
- 자동 재생 두 갈래: ① StageFile `autoSim` prop (런처 모달) ② `?sim=1` 쿼리 (마운트 후
  읽음) — 둘 다 이동 경로 탭 + StageRouteMap `autoSim`(초기 상태로만 소화)으로 흐른다.
- 시뮬 가능 판정은 `app/data/sim-stages.json`(build-enemies.py 산출, 28KB) — 경로가
  있으면 스폰 타임라인도 항상 있다 (2026-08-10 전수 확인). 경로 없는 작전은 런처
  검색에서 '경로 데이터 없음'을 달고 ?sim=1 없이 상세로 보낸다.
- 런처는 SEO 표적 페이지라 home.tsx가 **정적 임포트**한다 — lazy로 바꾸면 /sim HTML이
  빈 껍데기가 된다. 1.4MB 작전 데이터는 컴포넌트 안에서 지연 로드.

## ★ 한 화면 규칙 — **어느 작전도 탭으로 나누지 않는다** (사용자 확정 2026-09-23)

> "앞으로 모든 작전 스테이지에 대해서는 지금처럼 합쳐진 상태로 처음부터 만들어지게 룰 적어줘"
> — 새 작전(점검 당일 VS-1)이 '실사 도면 | 이동 경로' 두 탭으로 나뉘어 나온 뒤 받은 지시.

적용: 작전 도감 상세(StageFile — 본·통합전략·생존연산, 작전 시뮬레이터 모달도 이것) · /rogue 전투 노드 모달 ·
/ra 지역·전투 지형 모달. **`.st-maptabs`·`.rg-maptabs` 탭은 코드·CSS 모두 지웠다 — 되살리지 말 것.**
고르는 순서는 하나뿐이다:

1. **실사 미리보기 + 전투 카메라(`cam`, 또는 생존연산 `ortho`)** → 합친 도면 (아래 절). 경로가 없으면 도면만.
2. 그 밖에 **경로가 있으면 → 경로 지도 하나** (격자·경로·시뮬). 카메라 없는 도면은 게임이 미리보기를 주지 않아
   레벨 격자로 그린 그림뿐이라(2026-09-23 전수 248/248, KR·CN CDN 모두 미리보기 없음) 같은 격자를 그리는
   경로 지도로 잃는 게 없다. (예외: /ra 비평면도 20곳은 지역 그림 대신 경로 지도가 나온다 — 격자 여백이 달라
   평면도 정합에서 빠진 것. 맞추려면 그 그림들의 격자 몫을 따로 재야 한다.)
3. **경로도 없으면 → 도면 한 장** (팬위키 실사 스크린샷 156장이 전부 이쪽 — 경로 없는 작전이다).

데이터 조건 — 이게 빠지면 새 작전이 두 탭이나 빈 화면으로 나온다:
- **경로 유무는 레코드의 `sim` 표식으로 연 순간 안다** (build-stages.py 가 sim-stages.json 으로 단다 · 통합전략·
  생존연산 색인도 같은 뜻). 경로 파일(5MB)을 받아 봐야 알면 그림이 먼저 떴다가 지도로 바뀌며 출렁인다.
  /rogue 는 색인이 없어 열자마자 경로 파일을 받는다(합친 도면과 같은 파일).
- **카메라는 새 작전도 첫 빌드에 붙어야 한다** — `stagecams.attach` 가 "512 미리보기인데 카메라 없음"을 보면
  12시간 캐시를 무시하고 원본을 **한 번 새로 받아** 다시 찾는다 (점검 당일 12:42 캐시를 그대로 써서 16시 새 작전이
  빠진 것 — 원본엔 이미 들어와 있었다). 원본에 아직 없으면 그 작전은 2번(경로 지도)으로 나오고, 다음 갱신에서
  카메라가 붙으면 저절로 1번이 된다. 점검 반영 뒤 `build-stages.py` 출력의 `카메라(ko)` 수가 줄지 않았는지 본다.

## 실사 도면 합치기 — 실사 위에 경로·시뮬 (2026-09-23 사용자 요청)

> "실사 도면 위에 적 경로가 표시되고 시뮬레이트 가능하게 하나로" → 카메라가 있는 작전은
> **도면·이동 경로 두 탭이 한 화면**이 됐다. 카메라가 없는 작전은 위 ★ 한 화면 규칙을 따른다.

- **실사 도면의 정체**: 전투 카메라로 찍은 **16:9 화면을 512×512 정사각에 눌러 담은 그림**.
  카메라는 기울기 30°·세로 화각 반각 20°가 공통이고 **위치만 레벨마다** 다르다.
  투영식은 `app/stage-cam.ts` 하나뿐이다 (0-1 실측: 맞추는 데 안 쓴 바닥 이음새 예측 y=234.0
  = 실제 234, 바닥 오차 평균 0.5px · 16-15(x=−9)·14-16·고난 12-17·14-9·록라·보안 파견까지 육안 대조).
- **표시 비율 16:9** (`PHOTO_ASPECT`) — 정사각 원본을 편다. 실사 도면을 보여 주던 `.st-map` 과 같은
  비율이고, 펴면 게임 화면 비율로 돌아온다 (사용자 지시 "실사 도면이랑 같은 가로세로 배율로").
- **카메라 위치 = `Stage.cam`** (`scripts/stagecams.py` → stages*.json · stages-rogue*.json).
  레벨 파일에는 없다. 맵 씬 번들의 `_mapSettings.cameraView`(프리셋 번호)만으로도 안 정해진다
  (12-6·13-8 둘 다 3번인데 위치가 다름). 게임 코드를 역공학해 레벨별로 뽑아 둔
  **yuanyan3060/ArknightsGameResource 의 levels.json**(MAA 가 쓰는 것과 같은 출처, 매일 갱신)을 받는다.
  **도면이 512×512 인게임 미리보기일 때만** 붙는다 — 위키 스크린샷(640×360 등)·격자 렌더는 같은
  카메라로 찍힌 그림이 아니다. 고난판 도면이 일반판 **복사본일 때만** 일반판 카메라를 쓴다
  (tough_12-17 은 자기 도면·자기 카메라가 따로 있다).
- **렌더**: 도면은 진짜 `<img>`(서버 렌더·검색에 박힌다)이고 경로 SVG 를 같은 16:9 상자에 투명하게
  겹친다(`.st-photomap` · `.st-routeoverlay`). 좌표만 투영하고 선 굵기·점선·말 크기는 화면에서 일정 —
  단위를 도면 가운데 한 칸 폭으로 잡아 격자 모드와 같은 숫자를 쓴다. 흰 고지대 위에서 선이 묻히지
  않게 실사 모드만 어두운 밑선을 깐다. ▦ 타일 표시 = 타일 종류를 반투명 사각형으로 겹친다(기본 끔).
- **경로가 오기 전(pending)**: `data` 없이도 같은 자리·같은 모양(비활성 버튼 줄 + 16:9 도면)을
  그린다 — CLS 0. 데이터가 오면 `key` 가 바뀌어 다시 마운트된다 (autoSim 초기값을 데이터와 함께 소화).
- 보안 파견 긴급 판(ae)은 일반판의 도면·카메라를 쓰고 경로만 자기(_ex) 레벨 것이다.
- **평면도 모드**(`photo` 에 cam 없음): 생존연산 사막 이야기 도면은 격자를 바로 위에서 그린 평면도라
  (그림 비율 = 격자 비율인 86/106장) 원근 없이 격자 좌표를 그대로 쓰고 상자 비율을 격자 비율(w:h)로 둔다.
  ⚠ **격자는 그림 가운데 5/6 만 차지한다**(`SANDBOX_GRID_SHARE`, 가장자리 1/12 여백) — 1로 두었더니 가장자리
  출현 칸이 1~2칸씩 어긋났다 (사용자 제보 2026-09-23 "나오는 데·들어가는 데가 안 맞는다"). 격자선만 보고
  맞다고 하지 말 것 — 균일 격자는 배율·뒤집기가 틀려도 선이 맞아 보인다. **출현·도착 칸을 표식과 대조**한다. 그림을 16:9 로 펴지 않는다 (/ra 의 `.sb-origmap` 원칙). 나머지 20장·재기동 앵커
  썸네일은 ★ 한 화면 규칙대로 경로 지도 하나.
- 합친 도면은 **세 화면 공통**이다 — 작전 도감 상세(본·통합전략·생존연산)·/rogue 전투 노드 모달·/ra 지역 모달
  (사용자 요청 2026-09-23 "통합전략·생존연산도 마찬가지로, 형식 맞춰"). 통합전략·생존연산 작전은 작전
  시뮬레이터 검색에도 잡힌다 (색인의 `sim:1`, 추천 띠는 본 도감 작전만).
- ⚠ 고지대 윗면은 바닥보다 조금 높다(씬 `highlandHeight`, 0-1은 0.2) — 타일 겹치기는 바닥
  발자국이라 흰 블록 윗면이 몇 px 위로 떠 보인다. 경로·말은 바닥이라 영향 없다.

## 성능 규칙

- 경로 JSON은 크다(stage 5.3MB·gzip 0.8MB, rogue 1.4MB) — 합친 도면 작전은 **상세를 열 때**, 카메라 없는 작전은
  **'이동 경로' 탭을 처음 눌렀을 때만**
